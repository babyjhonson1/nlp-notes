# inference/continuous-batching: уточнения от 2026-10-09

## Источники и расчёты

- В [CacheConfig vLLM v0.31.0](https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/config/cache.py) непосредственно проверено `gpu_memory_utilization = 0.92`. В таблице исправлено значение по умолчанию; пример по-прежнему явно выбирает 0.9, что теперь объяснено комментарием.
- Точные параметры прежнего примера Llama-2-7B дают `2 * 32 * 32 * 128 * 2 = 524288` байт = 0.5 МиБ на токен; 4096 токенов — 2 ГиБ. Для Llama-3.1-8B при 8 головах K/V — 131072 байта = 128 КиБ.
- В `cb-roofline` заменено округление `KVT = 5e5` точным `524288`. Остальные условные параметры модели времени сохранены: 14e9 байт весов, 3e12 байт/с, 6e14 FLOP/с, 58e9 байт под кеш. Это оценка, не измерение.
- Вместимость 58 десятичных ГБ: `floor(58e9 / (2048 * 524288)) = 54`, при 8192 токенах — 13 последовательностей. Соответствующие числа в тексте согласованы с иллюстрацией.
- ITL описывает отдельные промежутки, TPOT — среднее по промежуткам запроса, а не синоним каждого ITL. При выводе пачки спекулятивных токенов нельзя отождествлять отдельный интервал с вычислительным шагом.
- Инвариантность к батчу ограничена поддерживаемой конфигурацией. См. [документацию воспроизводимости vLLM 0.31](https://docs.vllm.ai/en/v0.31.0/usage/reproducibility/) и разбор seed в новом разделе.
