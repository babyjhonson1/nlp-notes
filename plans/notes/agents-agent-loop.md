# Устройство агента: источники и проверка

Дата: 2026-10-07. Раздел `agents/agent-loop`.

## Первоисточники

- [ReAct, arXiv v3](https://arxiv.org/html/2210.03629v3), раздел 2: контекст взаимодействия, действия и наблюдения; раздел 3.1: search, lookup и finish. ICLR 2023, препринт 2022. В конспекте не воспроизводятся benchmark-числа, обучение и подробности рассуждений; формализация собственного цикла не объявляется спецификацией ReAct.
- [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents), 2024-12-19: принятое авторами различие предписанного управления и выбора следующих действий моделью. В статье есть примечание об изменении инструментария после 2024 года; перечень актуальных SDK и рекомендации по конкретным продуктам из неё не переносились.
- [How tool use works](https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works), проверено 2026-10-07: структурированный запрос, исполнение и возврат результата; клиентский цикл с tool_use/tool_result и размещение серверного исполнения. Эти названия блоков указаны как пример Claude, а не общий стандарт.

## Происхождение примера

Портал, `ACCESS_CHECK_FAILED`, инструкция `access-17`, сервис `auth` и инцидент вымышлены. Текст, Python-инструменты и иллюстрация описывают один пример. Результаты инструментов — наблюдения об источниках, а не доказательство полной причинной диагностики.

В Python, тексте и иллюстрации бюджет включает финальное решение: три решения / два инструмента дают completed, два решения дают step_limit после второго наблюдения. blocked завершает текущий запуск; пользователь может предоставить данные для нового запуска.

## Границы проверки

Выполнены `python3 tools/check.py` и проверка синтаксиса всех `assets/*.js` / `figures/*.js`. Оба Python-блока извлечены из HTML с декодированием сущностей и исполнены на Python 3.13.2: штатная траектория completed, пределы 1/2/3, соответствие call_id, получение инструкции в следующем контексте, blocked при нормальном статусе и TimeoutError, нарушения контракта, изоляция журнала и явное исключение заглушки. Для дополнительных веток использован локальный детерминированный обработчик контекста, не LLM.

В Node проверены девять траекторий иллюстрации (три ответа статуса и три лимита), неизменность ранних снимков и отсутствие наблюдения до возврата инструмента. На лёгкой подстановке DOM проверены переходы вперёд/назад, смена результата, сброс, предел и очистка обработчиков. Это проверка логики и обработчиков, не браузерного DOM и не визуального расположения.

Модели и бенчмарки не запускались, веса не скачивались. Учебные решения не проверяют качество выбора действий или ответа LLM. Браузер не открывался; визуальная проверка остаётся пользователю.
