# Оценка и диагностика RAG — техническая запись

Дата: 2026-10-09.

## Источники и границы

- [Es et al., RAGAs, 2024](https://aclanthology.org/2024.eacl-demo.16.pdf), раздел 3: выделение утверждений, проверка поддержки и доля подтверждённых. Приведён протокол конспекта, не актуальный API библиотеки.
- [Gao et al., ALCE, 2023](https://aclanthology.org/2023.emnlp-main.398/): качество ответа и цитат. Простая precision по независимо подтверждающим связям в справочнике намеренно не отождествлена с более тонкой оценкой полезности ссылок ALCE.
- [Liu, Zhang, Liang, 2023](https://aclanthology.org/2023.findings-emnlp.467/): точность и полнота подтверждения ссылками.
- [Zheng et al., 2023](https://arxiv.org/abs/2306.05685): смещения LLM-as-judge; результаты по предпочтениям в диалогах не перенесены автоматически на фактическую оценку RAG.
- [Efron, 1979](https://doi.org/10.1214/aos/1176344552): основа бутстрепа. В конспекте — парная процентильная оценка; для связанных вопросов нужна групповая перевыборка.
- [trec_eval](https://github.com/usnistgov/trec_eval) упомянут только как пример инструмента расчёта метрик ранжирования.
- MMR: источник и условные оценки сохранены в [записи предыдущего раздела](rag-query-context.md). Добавлены справочная формула и карточка; алгоритм и иллюстрация не менялись.

## Соглашения примера

- Все вопросы, тексты ответов и диагностические результаты условные. Нет измерений генератора или модели-судьи.
- Два требования к доказательствам: процедура и срок. Три факта рубрики ответа: процедура с телефонной проверкой; администратор; срок со всеми условиями. Разные единицы выбраны явно и не смешиваются.
- A, B покрывают одно требование из двух; A, C — оба. Стоимости прежние: 270 и 240 при бюджете 300 условных токенов; токенизатор не запускался.
- Correctness — бинарная полная успешность по рубрике, не одноимённая взвешенная библиотечная оценка. Fact-level F1 — семантическое соответствие один к одному уникальных утверждений и обязательных фактов; для свободных добавлений нужна расширенная рубрика.
- Пустые знаменатели не превращаются в идеальные оценки. Отказы учитываются отдельно; средние снабжаются числом валидных/исключённых вопросов.
- Первоисточники поддерживают идеи оценки; соглашения о гранулярности, дубликатах и обработке пустых значений в тексте заданы как собственный явный протокол.
- RAG-часть generation-metrics заполнена; общие метрики других задач генерации пока не написаны, поэтому статус draft.

## Автоматические проверки

- `python3 tools/check.py`: без ошибок, 6 глав, 28 разделов, 46 зарегистрированных иллюстраций.
- `node --check assets/glossary.js` и `git diff --check`: без ошибок.
- Из HTML извлечены и выполнены именно четыре Python-примера: evaluation, query-context, generation-metrics, retrieval-metrics. Только стандартная библиотека, без моделей, сети и весов.
- Evaluation: средние 0.375 и 0.625, разность 0.25; 5000 парных перевыборок, Random(7), эмпирические квантили с линейной интерполяцией: интервал [-0.25, 0.75].
- Generation metrics: 0.667, 0.667; citation precision 1.0, recall 0.667. Проверены пустые множества и F1 для двух из трёх фактов (0.8).
- Query-context: порядок A, C, B; упаковка A, C, стоимость 240. Retrieval-metrics: прежние результаты примера 0.5, 0.442, 0.619.
- Проверены вложенность HTML, парность разделителей LaTeX, существование внутренних файлов и якорей в четырёх разделах.
- Реестр из 12 терминов проверен через Node VM: существование целевых якорей и формул. 25 кнопок в двух RAG-разделах проверены с DOM-заглушкой: регистрация, открытие по pointerenter/focus/click, содержимое формулы и ссылки, закрытие и aria-expanded.
- Это не браузерная проверка: верстка, реальный рендеринг MathJax, расположение карточки и мобильный тап остаются для проверки пользователем. Движок и CSS карточек не менялись.
