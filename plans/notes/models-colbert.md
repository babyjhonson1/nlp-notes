# ColBERT: источники и границы проверки

Обновлено 2026-10-08. Модели и токенизаторы в этой задаче не запускались.

## Существующие результаты

Прежние измерения токенизатора, характеристики чекпойнта, числа статей и проверки API сохранены в [архиве моделей, «4. ColBERT»](../archive/models-2026-10-07.md). Нельзя выдавать их за новые прогоны. Убраны из основной линии перечни задержек, настроек ANN, абляций и размеров полного индекса; механизм сжатия оставлен с расчётом 256 → 36 байт на вектор.

## Источники редакции

- [ColBERT](https://arxiv.org/html/2004.12832), §3: независимое кодирование, нормированная проекция, MaxSim, маркеры и query augmentation, обучение по тройкам.
- [ColBERTv2](https://arxiv.org/html/2112.01488), §3.2–3.5: списки кандидатов, учитель MiniLM, KL и in-batch loss, обновление выдачи, центроид и квантованный остаток.
- [colbert.py](https://github.com/stanford-futuredata/ColBERT/blob/main/colbert/modeling/colbert.py), compute_ib_loss: позитив своего запроса + все пассажи других запросов локального батча, без собственных негативов. [training.py](https://github.com/stanford-futuredata/ColBERT/blob/main/colbert/training/training.py): KL по своему списку и сумма с IB, учитель передан готовыми оценками. Рецепт и код не следует отождествлять с любой пользовательской конфигурацией.

## Формулы и условные примеры

- Производная MaxSim по готовым токенным векторам разрежена при уникальных максимумах. Это не означает нулевого градиента всех входных эмбеддингов невыбранных токенов: контекстуализация связывает позиции.
- Монотонность максимума при добавлении столбцов относится к фиксированной матрице сходств. Дописывание текста с перекодированием BERT — другая операция.
- Исходные учебные матрицы figures/colbert.js сохранены: 10 показанных строк из 32; суммы 6.4 и 5.7, P+ = 0.6681877722, loss = 0.4031860489. Это сокращённая условная задача, не оценка реальной модели.
- Новый пример KD: T=(0.60,0.35,0.05), P=(0.20,0.20,0.60), градиент P−T=(-0.40,-0.15,0.55). Все числа условные; роли документов соответствуют основному примеру.
- Полный MaxSim сжатого индекса считается по восстановленным приближённым векторам, не по исходным. Схема больше не называет его «точным».
