## Содержание и границы

Первый раздел: ограничение одиночного вызова → выбор между workflow и агентным управлением → разделение участников → цикл и обновление состояния → остановка → минимальная реализация без фреймворка. Формализация связывает журнал, контекст, решение и наблюдение с кодом; обзор MDP/POMDP и RL не нужен.

Второй раздел: вызов как текст в формате чекпойнта (шаблон чата, отдельные токены тегов, парсер сервера) → обучение на траекториях с маской потерь → Toolformer по шагам (позиции, кандидаты, исполнение, фильтр на трёх кандидатах A/B/C, дообучение, генерация; иллюстрация `tc-toolformer`) → траектории ToolLLM → что задают имя, описание и JSON Schema, стоимость описаний, поиск инструментов → цепочка проверок, ограниченное декодирование (формула маски, гарантии и границы), `tool_choice` → ошибка вызова как наблюдение, несколько вызовов в ответе → адаптер к OpenAI-совместимому серверу. Не здесь: механизм построения маски по автомату и влияние ограничений на качество подробно (`inference/structured-output`), MCP как протокол распространения инструментов, prompt injection через результаты инструментов (безопасность), бенчмарки вызова функций (оценка).

Память, планирование, multi-agent, MCP, безопасность и оценка — будущие самостоятельные разделы; их порядок пока не согласован. Не расширять готовые разделы каталогом технологий и не писать остальные без поручения.

## Особые договорённости

- Сквозной пример — условная диагностика `ACCESS_CHECK_FAILED`: поиск инструкции, при необходимости статус `auth`, затем ответ либо запрос недоступных данных. Нормальный статус не доказывает ошибку прав; инцидент не доказывает причину конкретного обращения.
- Один шаг бюджета — решение модели, включая завершение. Предложение вызова, его исполнение и запись результата показываются раздельно.
- Первый раздел: Python-цикл исполняемый; адаптер LLM не реализован, инструменты и решения учебного прогона условные. Иллюстрация демонстрирует заданные траектории без модели.
- Второй раздел: пример формата — шаблон чата Qwen3-4B-Instruct-2507 (Hermes-формат, парсер vLLM `hermes`), vLLM 0.31. Контракт второй версии: `completed` — текстовый ответ без вызова, `blocked` — служебный инструмент `ask_user` (проверяется, не исполняется), ошибки вызова — наблюдения, `max_steps=4`. Числа токенов — локальный подсчёт токенизатором чекпойнта; модель не запускалась. Пример Toolformer — фраза справки с `search_instruction`; вероятности и потери по токенам условные, взвешенные потери в тексте и иллюстрации совпадают (A проходит до \(\tau_f=1{,}56\), C — кандидат с продолжением в запросе).

## Открытые задачи

- Браузерную проверку выполняет пользователь.
