# Конспекты по NLP — правила для редакторов

Этот файл читают все агенты, которые правят сайт (Claude Code — через `CLAUDE.md`, Codex и другие — напрямую). Правила одинаковы для всех. Если просьба пользователя противоречит этим правилам, делай как просит пользователь, а при необходимости предложи обновить этот файл.

Сайт — личные конспекты по NLP, устроенные как тетрадь OneNote: главы → разделы. Читатель — человек с техническим образованием, который готовится к работе NLP-разработчиком: формулы и инженерные детали приветствуются, объяснять нужно строго и по существу, без научпопного упрощения. Материал строится вокруг переносимых идей, алгоритмов, метрик и компромиссов; API конкретных фреймворков разбираются только как практические примеры, без привязки всего конспекта к одному стеку. Язык сайта — русский.

## Порядок работы

1. Перед началом подтяни последние изменения (`git pull`): сайт правят из разных мест.
2. Прочитай `outline.json`, чтобы понять структуру. Тексты разделов целиком открывай только те, с которыми работаешь.
3. Перед тем как писать новый раздел, прочитай целиком хотя бы один готовый (например, `sections/rag/ann.html`) и выдерживай тот же тон, глубину и разметку.
4. Внеси правки.
5. Запусти `python3 tools/check.py` и исправь всё, что он нашёл.
6. Посмотри результат в браузере: `python3 -m http.server 8000` в корне репозитория, затем http://localhost:8000. Открывать `index.html` как файл с диска нельзя: оглавление и разделы грузятся через `fetch`.
7. Закоммить в `main` с понятным сообщением на русском («Новый раздел: чанкинг», «ANN: исправлена формула PQ») и сделай `git push`. GitHub сам запустит проверку и опубликует сайт; если проверка не прошла, сайт не обновится.

## Совместная работа нескольких агентов

- По умолчанию только один агент одновременно вносит изменения в текущий checkout. Закончив задачу, он запускает проверку, коммитит и отправляет изменения; следующий агент начинает с `git pull`.
- Не запускай Codex и Claude Code на запись в одном checkout одновременно: даже правки разных файлов могут пересечься в `outline.json`, `index.html` и Git-индексе.
- Если действительно нужна параллельная работа, используй отдельные ветки и отдельные worktree, заранее раздели файлы и своди изменения только после проверки каждой ветки.

## Структура репозитория

```
AGENTS.md                 ← эти правила (единственный источник)
CLAUDE.md                 ← подключает AGENTS.md для Claude Code
outline.json              ← оглавление: главы, разделы, служебные аннотации
sections/<глава>/<раздел>.html   ← тексты разделов (только содержимое, без <html>/<body>)
figures/common.js         ← общие помощники для иллюстраций
figures/<префикс>.js/.css ← интерактивные иллюстрации раздела
assets/core.js, assets/site.js, assets/site.css ← движок и оформление сайта
index.html                ← каркас страницы и подключение файлов
tools/check.py            ← проверка структуры и стиля
.github/workflows/pages.yml ← проверка и публикация на GitHub Pages
```

`assets/*`, `index.html` (кроме подключения новых файлов иллюстраций) и общий дизайн меняются только по прямой просьбе пользователя.

## Оглавление: outline.json

```json
{ "id": "rag", "title": "RAG", "color": "#2E6E73", "sections": [
  { "id": "ann", "title": "ANN: приближённый поиск ближайших соседей",
    "status": "done",
    "summary": "1–3 предложения: о чём раздел и что в нём разобрано.",
    "concepts": ["ANN", "recall@k", "HNSW"] }
]}
```

- `id` главы и раздела — латиница в kebab-case. После создания не меняется: на нём держатся ссылки (`#/rag/ann`) и путь к файлу `sections/rag/ann.html`.
- Порядок в массивах = порядок на сайте. Перестройка структуры — это правка `outline.json` (и перенос файла в `sections/`, если раздел переехал в другую главу). Тексты при этом не переписываются.
- `status`: `"empty"` — текста нет (файла нет или он пустой), `"draft"` — черновик, `"done"` — готово.
- `summary` (1–3 предложения) и `concepts` (3–10 ключевых понятий) на сайте не показываются: по ним работают со структурой, не читая тексты. **При каждом создании или изменении раздела обнови его `summary`, `concepts` и `status`.**
- Цвета глав. Заняты: `#2E6E73` (RAG), `#55609E` (Инференс LLM), `#9A5B2E` (Мультимодальные LLM). Для новых глав бери по очереди: `#6B7F2A`, `#A63D5A`, `#2F7FA8`, `#A47A1E`, `#4F5D73`.

## Новый раздел: по шагам

1. Добавь раздел в `outline.json` в нужную главу и на нужное место.
2. Создай `sections/<глава>/<раздел>.html` по шаблону ниже.
3. Если нужны интерактивные иллюстрации, создай `figures/<префикс>.js` (и при необходимости `.css`) и подключи их в `index.html` в блоках «Иллюстрации: стили» и «Иллюстрации: код» перед `assets/site.js`.
4. Заполни `summary`, `concepts`, `status`.
5. `python3 tools/check.py`, просмотр в браузере, коммит, push.

## Шаблон текста раздела

Заголовок раздела (`<h1>`) не пишется: сайт берёт его из оглавления.

1. `<p class="lead">` — вводный абзац, 3–6 предложений: какая задача, почему она важна, в чём суть подхода.
2. Содержание раздела по заголовкам `h2`:
   ```html
   <nav class="toc" aria-label="Содержание раздела">
     <p>Содержание</p>
     <ol><li><a href="#" data-jump="ann-task">Задача и метрики качества</a></li></ol>
   </nav>
   ```
   У каждого `h2` есть `id` вида `<префикс раздела>-<слово>` (`ann-task`, `cb-why`). Префикс один на весь раздел и уникален на весь сайт; тот же префикс используют иллюстрации раздела.
3. Основная часть: блоки `h2`, внутри при необходимости `h3`. Глубже `h3` не уходить.
4. Предпоследний `h2` — применение на практике: библиотеки, параметры, код.
5. Последний `h2` — «Ключевые статьи», список вида `Авторы. <i>Название</i>, год — чем важна.`

Термин при первом упоминании: русское название и английское в скобках, например «векторная база (vector database)». Важное обобщение или вывод — в `<div class="note"><p>…</p></div>`. Таблицы оборачиваются в `<div class="table-wrap">`. Код — `<pre><code>`, внутри `<` пишется как `&lt;`, `&` как `&amp;`. Картинки — только inline SVG или `data:` URI.

## Формулы — только LaTeX

- Любая математика, включая одиночные переменные и индексы, набирается в LaTeX: строчные формулы `\( ... \)`, выносные — отдельным абзацем `<p class="formula">\[ ... \]</p>`. Рисует MathJax 3 (SVG).
- Нельзя набирать математику через `<i>`, `<sub>`, `<sup>` и символы Unicode (`·`, `‖`, `ℝ`, `²`, `α`, `≈`). Знак `$` разделителем формул не служит.
- Внутри формул `<` пишется как `&lt;`, `&` как `&amp;` (например, в `cases`).
- Слова внутри формул — `\text{...}`, имена функций — `\operatorname{...}` или `\log`, `\exp`, `\max`.
- В текстах иллюстраций (пояснения `fig-say`, подписи, кнопки) формулы тоже LaTeX. В JS-строках обратный слэш удваивается: `"\\(x_{1}\\)"`. Внутри SVG (элементы `<text>`) LaTeX не работает — там только простые подписи.

## Иллюстрации

Иллюстрации нужны там, где они заметно упрощают понимание ёмкого алгоритма, процесса или компромисса: показывают работу по шагам, влияние параметра или сравнение режимов. Не добавляй декоративные схемы и не иллюстрируй каждый термин; один содержательный интерактивный рисунок может закрывать несколько близких методов. Для алгоритмов уровня HNSW предпочтительны пошаговый проигрыватель, ползунок параметра или переключение режимов.

В тексте раздела:

```html
<figure class="fig" data-figure="cb-flat">
  <div class="fig-box" data-mount></div>
  <figcaption>Что показано и что можно делать.</figcaption>
</figure>
```

Код — функция `mountИмя(box)` в `figures/<префикс>.js`, зарегистрированная в конце файла:

```js
Object.assign(FIGURES, {
  "cb-flat": mountCbFlat
});
```

Функция может вернуть функцию очистки (снять таймеры и обработчики). Имена иллюстраций, функций и CSS-классов — с префиксом раздела. Общие помощники (`rng`, `legend`, `ICON`, `vlControls`, `vlPlayer`, `cbFit` и другие) лежат в `figures/common.js` и в файлах уже готовых иллюстраций — переиспользуй их, а не пиши заново. Цвета берутся из CSS-переменных (`--chapter`, `--fig-accent`, `--g1`…`--g4` и т. д.), чтобы работала тёмная тема.

**Порядок блоков внутри иллюстрации: картинка (`fig-stage`) → управление (`fig-row`: кнопки шагов, ползунки, переключатели) → текст пояснения (`fig-say`) → легенда (`fig-legend`).** Управление никогда не ставится под `fig-say`: длина текста меняется от шага к шагу и не должна сдвигать кнопки.

## Чего не делать

- Не менять `id` существующих глав и разделов.
- Не трогать дизайн, `assets/*` и общие стили без прямой просьбы.
- Не подключать внешние картинки и сторонние библиотеки без необходимости; если библиотека нужна, только с cdnjs.cloudflare.com с фиксированной версией.
- Не коммитить, если `python3 tools/check.py` выдаёт ошибки.
