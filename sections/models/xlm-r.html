XLM-R — один кодировщик для текстов на многих языках. Его предобучение устроено как у BERT: по окружающему контексту нужно восстановить скрытые токены, но общие параметры обновляются на текстах сразу ста языков. Затем модель можно дообучить на размеченной задаче, например на английских парах предложений, и проверить ту же модель на русском без русского дообучения. Главный вклад XLM-R — масштаб многоязычных данных и рецепт их использования, а не новая архитектура attention. При этом XLM-R остаётся основой для прикладных моделей: готовым поисковым эмбеддером его делает отдельное обучение.

Что общее у ста языков

У XLM-R один трансформер-кодировщик, одна таблица входных эмбеддингов и один подсловный словарь SentencePiece. Русский и английский тексты проходят через те же слои. Часть токенов общая — например, цифры и некоторые имена; другие характерны для отдельных языков, но отдельного набора весов для каждого языка нет.

Модель не получает специальный идентификатор языка. Она должна использовать сам текст; это также позволяет подать смешанный русско-английский вход без назначения одной метки всей последовательности. Отдельных эмбеддингов сегментов для двух предложений нет. При обработке пары токенизатор ставит разделители:

<s> первое предложение </s></s> второе предложение </s>

Это не сиамская схема SBERT: когда пару подают так, внимание охватывает оба предложения. Но в предобучении пара с меткой ещё не нужна — следующий этап работает с обычным текстом.

Предобучение: один текст, скрытые токены, одна ошибка

Откуда берётся обучающий пример

Корпус CC-100 собран из очищенных страниц Common Crawl на ста языках. Это независимые тексты, а не выровненные переводы: английская страница не обязана иметь русскую пару. Веб-данные особенно важны для языков, чьи Википедии слишком малы для предобучения. Подготовка по конвейеру CCNet удаляет повторы и шаблонные фрагменты, определяет язык и фильтрует тексты языковыми моделями. Цель — получить связный текст нужного языка; такие фильтры не гарантируют ни истинности фактов, ни отсутствия смещения в составе корпуса.

После токенизации выбирают \(15\%\) позиций. На выбранной позиции в \(80\%\) случаев ставят <mask>, в \(10\%\) — случайный токен, в остальных \(10\%\) оставляют исходный. Правильная цель во всех случаях одна — исходный токен в этой позиции. Это маскированное языковое моделирование (masked language modeling, MLM).

Условный текст: «Поисковая система получает короткий запрос и находит абзацы, которые на него отвечают». Ниже — три фрагмента этого примера, а не три отдельных обучающих текста. Разбиение на токены проверено ранее, выбор масок сделан вручную:

Исходные токены фрагментаЧто осталось на входеЦель в выбранной позиции
▁получает ▁короткий ▁запрос▁получает <mask> ▁запрос▁короткий
▁на ходит ▁абзац ы▁на <mask> ▁абзац ыходит
▁него ▁отвечаю т▁него <mask> т▁отвечаю

Маскируется подслово, не обязательно целое слово: в «находит» на входе сохранилась первая часть. Модель получает весь испорченный фрагмент, поэтому для восстановления доступны токены по обе стороны маски.

Что вычисляется и что обновляется

Кодировщик выдаёт вектор \(h_i(\tilde x)\) каждой позиции испорченного текста \(\tilde x\). MLM-голова преобразует его в логиты словаря; softmax даёт \(p_\theta(w\mid\tilde x,i)\). Правильный класс — исходный токен \(x_i\), а не язык текста и не его перевод. Для множества выбранных позиций \(M\) потери одного примера:

\[\ell_{\mathrm{MLM}}(x)=-\frac{1}{|M|}\sum_{i\in M} \log p_\theta(x_i\mid\tilde x,i).\]

Собственные слагаемые ошибки есть только у выбранных позиций. Но градиент не ограничен этими токенами: через внимание он проходит и к представлениям видимого контекста, а затем в общие слои и входные эмбеддинги. Выходная проекция MLM использует общую с входом таблицу эмбеддингов; учатся и кодировщик, и MLM-голова.

Декодера здесь нет. XLM-R не восстанавливает отрезок токен за токеном и не подставляет свою догадку для предсказания следующей маски: все целевые распределения вычисляются по одному испорченному входу. Это отличие от T5. Общая формула и назначение замен \(80/10/10\) — в справочнике MLM.

Как распределить обучение между языками

Если просто перемешать все предложения, крупные языковые корпуса будут определять почти каждое обновление. Обратная крайность — брать все языки одинаково часто: тогда небольшой корпус будет многократно повторяться, пока большой используется лишь частично. XLM-R выбирает промежуточный вариант.

Пусть \(n_\ell\) — число предложений языка \(\ell\). Вероятность выбора языка для батча задаётся так:

\[q_\ell=\frac{n_\ell^\alpha}{\sum_k n_k^\alpha},\qquad\alpha=0.3.\]

При \(\alpha=1\) выборка пропорциональна размеру, при \(\alpha=0\) — равномерна по языкам. Условно, если одного языка в сто раз больше, при \(\alpha=0.3\) он будет выбираться лишь в \(100^{0.3}\approx4\) раза чаще. Формула не добавляет данных: она перераспределяет, на каких данных тратится фиксированный бюджет обновлений.

Чем меньше \(\alpha\), тем больше обучающего сигнала получает малый язык, но тем меньше разнообразие повторно используемых примеров. Оптимальное значение зависит от цели и корпуса; \(0.3\) — выбор рецепта XLM-R, а не универсальная константа многоязычного обучения. Та же форма выборки используется у mT5.

Дообучение и перенос на другой язык

После восстановления токенов — классификация пары

Предположим, нужна NLI-классификация: следует ли гипотеза из посылки, противоречит ей или сведений недостаточно. MLM-голова для этого не нужна. Берут предобученный кодировщик, добавляют новую классификационную голову \(C_\phi\) над выходом начального <s> и подают пару целиком с разделителями.

Условный английский пример: посылка “The Irish Sea separates Great Britain from Ireland.”, гипотеза “A sea separates the two islands.”, метка — следование. Готовая разметка MultiNLI даёт такие пары и метки; модель не выводит метку из факта соседства текстов.

\[o=\operatorname{softmax}\!\left(C_\phi(h_{\langle s\rangle}(a,b;\theta))\right),\qquad \ell_{\mathrm{NLI}}=-\log o_y.\]

Теперь softmax идёт по трём отношениям, не по словарю. Градиент меняет и новую голову \(\phi\), и предобученный кодировщик \(\theta\). Все токены пары могут взаимодействовать через внимание. После дообучения остаётся эта голова с кодировщиком; MLM-голова не участвует.

Что означает «перенос без переводов»

Далее той же обученной модели подают русскую пару: «Ирландское море отделяет Великобританию от Ирландии» и «Два острова разделены морем». Если её дообучали только на английских примерах, это проверка межъязыкового переноса (cross-lingual transfer): новых русских обновлений весов перед предсказанием нет.

Общие слои уже учились извлекать контекст на разных языках, поэтому часть признаков, полезных английскому классификатору, может оказаться полезной и для русского. Это эмпирическое свойство совместного предобучения, не математическая гарантия MLM. Исследования переноса показывают, что общий словарь помогает, но одних совпадающих токенов недостаточно для объяснения: перенос наблюдается и при раздельных словарях с общими слоями. Из этого не следует, что переводы обязаны получить одинаковые векторы.

В экспериментах на XNLI важно не смешивать три режима:

РежимНа каких примерах дообучаютЧто проверяют
Перенос с английскогоАнглийские пары MultiNLI с метками.Тот же классификатор на тестах других языков.
Обучение на переводах (translate-train / translate-train-all)Переводы английских обучающих пар с сохранёнными метками, на одном или на всех целевых языках.Качество после явного многоязычного дообучения; это уже не обучение только на английском.
Перевод теста (translate-test)Обучение может оставаться английским.Тестовый вход сначала переводят на английский; оценивается конвейер с переводчиком.

Русские переводы в dev и test XNLI — данные проверки, а не свидетельство использования параллельных текстов в предобучении. В статье XLM-R large даёт \(80.9\%\) средней точности по \(15\) языкам при переносе с английского и \(83.6\%\) при обучении на всех переводах. Эти числа сравнивают конкретные режимы на XNLI; они не обещают тот же прирост на произвольной задаче. Выбор чекпойнта авторы делали по объединённому dev разных языков, что тоже важно при воспроизведении режима.

Ёмкость модели: большой кодировщик или большой словарь

Совместное обучение может помогать языкам за счёт общих закономерностей, но они также конкурируют за ограниченные параметры и бюджет обновлений. В абляциях авторов добавление языков сначала помогало, а дальнейшее расширение набора при фиксированном размере ухудшало качество — это названо проклятием многоязычности (curse of multilinguality). Это наблюдение при конкретных условиях, не правило «многоязычная модель всегда хуже одноязычной».

Здесь полезно разделить два способа увеличить ёмкость:

ВариантЧто увеличеноКакую проблему решаетЦена
XLM-R large, затем XL/XXLЧисло и/или ширина слоёв кодировщика.Больше возможностей моделировать контекст разных языков общими слоями.Больше памяти и вычислений самого трансформера.
XLM-VСловарь, построенный с учётом групп лексически близких языков.Меньше дробление слов на короткие фрагменты; вход может стать короче.Больше таблица эмбеддингов и дороже словарный softmax при MLM.

У XLM-R base уже около \(192\) млн параметров приходится на таблицу \(250\,002\times768\), а не на слои внимания. Поэтому сравнивать размеры по одному общему числу параметров недостаточно. При использовании кодировщика без MLM-головы из таблицы выбираются строки; при предобучении голова должна ещё вычислять оценки по всему словарю. Утверждение «большой словарь стоит только памяти» для MLM неверно.

XL/XXL также изменили размещение нормировки на pre-LN. Это более крупные предобученные кодировщики, а не специальные режимы исходного base. Они использовали другой бюджет обучения; разницу результатов нельзя автоматически приписать только числу параметров.

Что важно при использовании

Классификатор переноса — ещё не поисковый эмбеддер

MLM учит восстанавливать токены, а NLI-классификатор выше совместно читает пару. Ни одна из этих целей не требует, чтобы косинус независимо усреднённых векторов предложений был хорошей мерой релевантности. В исследовании Reimers и Gurevych среднее по токенам XLM-R давало на межъязыковом STS 2017 корреляцию Спирмена \(17.8\) по шкале, умноженной на \(100\); после дистилляции от SBERT-перефразировок — \(83.7\). Это результат конкретного сравнения, а не доказательство, что улучшить эмбеддинги можно только переводными парами.

Для поиска используют отдельно обученные представления — например, multilingual-e5, BGE-M3 или многоязычный SBERT. От XLM-R они получают основу, но добавляют собственные данные, цели, пулинг и формат входа.

Токенизатор и длина — часть модели

У base/large предел входа — \(512\) токенов вместе со специальными. Это не фиксированное число русских слов: число подслов зависит от текста. В конфигурации есть \(514\) позиционных эмбеддингов, но нумерация настоящих позиций начинается с \(2\); две дополнительные строки не дают два дополнительных токена контекста.

В прежней проверке токенизатор сохранял регистр, но нормализовал некоторые символы: м² превращалось в м2, № — в No, переносы и табуляции — в пробелы. Это потеря различий ещё до кодировщика. Пары передают токенизатору двумя аргументами, чтобы он сам поставил правильные разделители. Ни ручные метки языка, ни префиксы эмбеддеров базовой XLM-R не требуются.

Рецепт целиком: выбрать язык → взять одноязычный текст → скрыть токены → обновить общий кодировщик по MLM → дообучить на нужную задачу. Перенос на другой язык и качество косинусных эмбеддингов — разные свойства; каждое проверяют своей задачей.

XLM-R на практике

Заполнение пропуска

from transformers import pipeline

fill = pipeline("fill-mask", model="FacebookAI/xlm-roberta-base")
print(fill("Столица России — <mask>."))   # маска — <mask>, а не [MASK]

Код составлен по документации transformers и не запускался.

Один шаг дообучения классификатора пар

import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification

name = "FacebookAI/xlm-roberta-base"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForSequenceClassification.from_pretrained(name, num_labels=3)
optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5)

# Условная договорённость: 0 — следование, 1 — нейтрально, 2 — противоречие.
# Новая голова изначально случайна; это только один шаг, не готовое обучение.
model.train()
x = tok(
    ["The Irish Sea separates Great Britain from Ireland."],
    ["A sea separates the two islands."],
    truncation=True, max_length=128, return_tensors="pt"
)
optimizer.zero_grad(set_to_none=True)
loss = model(**x, labels=torch.tensor([0])).loss
loss.backward()
optimizer.step()

Фрагмент показывает, какие параметры получают обновление. Для реального обучения нужны цикл по размеченным батчам и проверка на dev; один пример не обучает перенос между языками. Проверять русские пары нужно уже после этого, с model.eval() и без вычисления градиентов. Оптимизатор разобран в справочнике Adam/AdamW. Пример с моделью не запускался.

Ключевые статьи

  • Conneau et al. Unsupervised Cross-lingual Representation Learning at Scale, 2019 — XLM-R: корпус CC-100, словарь SentencePiece на 250 тыс. токенов, выборка языков с \(\alpha=0.3\) и анализ проклятия многоязычности.
  • Lample, Conneau. Cross-lingual Language Model Pretraining, 2019 — XLM: общий словарь, формула выборки языков, MLM на потоках текста, TLM на параллельных данных и эмбеддинги языков.
  • Liu et al. RoBERTa: A Robustly Optimized BERT Pretraining Approach, 2019 — рецепт предобучения, который XLM-R перенёс на 100 языков: дольше, большими батчами, без задачи следующего предложения.
  • Wenzek et al. CCNet: Extracting High Quality Monolingual Datasets from Web Crawl Data, 2019 — конвейер, которым собран CC-100: удаление повторов, определение языка и фильтр языковой моделью.
  • Wu, Conneau, Li, Zettlemoyer, Stoyanov. Emerging Cross-lingual Structure in Pretrained Language Models, 2019 — почему перенос работает без переводов: решают общие параметры, а не общий словарь.
  • Goyal et al. Larger-Scale Transformers for Multilingual Masked Language Modeling, 2021 — XLM-R XL и XXL: при большей ёмкости многоязычная модель догоняет одноязычную на английском.
  • Liang et al. XLM-V: Overcoming the Vocabulary Bottleneck in Multilingual Masked Language Models, 2023 — словарь почти на миллион токенов, построенный по группам языков.
