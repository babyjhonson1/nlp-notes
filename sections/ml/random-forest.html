Глубокое дерево умеет находить сложные правила, но слишком сильно зависит от конкретной обучающей выборки: несколько изменившихся заказов могут перестроить целую ветвь. Бэггинг (bagging, от bootstrap aggregating) использует эту неустойчивость: обучает много немного разных моделей и объединяет их ответы. Случайный лес (random forest) развивает идею — дополнительно ограничивает выбор признаков, чтобы деревья меньше повторяли друг друга. Разберём, откуда берутся разные деревья, почему их среднее устойчивее и как оценить качество без отдельного обучения на каждом фолде. Пример остаётся прежним: по признакам заказа предсказываем негативный отзыв.

Почему одного дерева мало

В предыдущем разделе дерево сначала спрашивало о задержке доставки, затем о цене. Но если убрать часть заказов или несколько раз повторить другие, лучшим первым вопросом может стать вопрос о цене. После него объекты распределятся по узлам иначе, и следующие вопросы тоже изменятся. Особенно сильно меняются маленькие листья: их ответ мог держаться на одном случайном отзыве.

Есть два способа сделать прогноз устойчивее. Первый мы уже знаем: ограничить глубину или увеличить минимальный размер листа. Цена этого решения — потерянные закономерности. Например, дерево из одного вопроса не выразит правило «от дорогой покупки ждут большего, но только при небольшой задержке». Второй способ — сохранить достаточно сложные деревья, но усреднить их ответы. Такой набор совместно используемых моделей называют ансамблем (ensemble).

Замысел простой: одно дерево случайно завысит риск негатива, другое занизит, а средний прогноз будет меньше зависеть от отдельного неудачного разбиения. Но обучить сто одинаковых деревьев на одинаковых данных бесполезно — среднее одинаковых ответов ничего не изменит. Сначала нужно получить различающиеся деревья.

Бутстрэп: разные выборки из одних данных

Выбираем с возвращением

Бутстрэп-выборку (bootstrap sample) получают случайным выбором объектов с возвращением. Выбрали заказ, записали его и вернули обратно: на следующем шаге он снова может попасться. Выбирают целые строки, то есть признаки вместе с целевой меткой. В обычном бэггинге из исходных \(n\) строк делают ровно \(n\) таких выборов.

Возьмём десять заказов предыдущего раздела, с номерами от 1 до 10. Три возможные бутстрэп-выборки показаны ниже; повтор номера означает повтор той же строки, а не новый заказ. Пример условный.

Для дереваНомера выбранных заказовРазличных заказовНе попали в выборку
11, 2, 2, 2, 3, 4, 5, 7, 7, 8\(7\)6, 9, 10
21, 2, 3, 4, 5, 5, 6, 9, 9, 9\(7\)7, 8, 10
31, 3, 4, 4, 5, 5, 5, 5, 5, 6\(5\)2, 7, 8, 9, 10

На каждой строке таблицы обучаем отдельное дерево обычным способом. Во второй выборке заказ 9 участвует в подсчёте Gini и долей классов трижды, а заказ 7 не участвует вовсе. Поэтому меняются лучшие пороги и ответы листьев. Новых сведений бутстрэп не создаёт: он меняет вес уже известных наблюдений. Бэггинг предложен именно как способ объединять такие версии модели; наибольшая польза ожидается от методов, чувствительных к изменениям данных (Breiman, 1996).

Почему различных объектов около двух третей

Для конкретного заказа вероятность не попасть в один случайный выбор равна \(1-1/n\). Чтобы не попасть в выборку совсем, нужно пропустить все \(n\) независимых выборов. Поэтому

\[P(\text{заказ не выбран})=\left(1-\frac1n\right)^n,\qquad P(\text{заказ выбран хотя бы раз})=1-\left(1-\frac1n\right)^n.\]

При \(n=10\) вторая вероятность равна примерно \(0.651\): ожидаем \(6.51\) различных заказов из десяти. Это среднее по многим выборкам, поэтому наши \(7\), \(7\) и \(5\) ему не противоречат. При большом \(n\) доля стремится к \(1-1/e\approx0.632\). Остальные примерно \(36.8\%\) объектов для данного дерева называются вневыборочными (out-of-bag, OOB). Они понадобятся для оценки качества.

«В бутстрэп попадает \(63.2\%\) данных» означает долю различных исходных объектов. Строк в выборке по-прежнему \(n\), просто некоторые повторяются. Это не разбиение исходных данных на постоянные train и validation: у каждого дерева свой набор пропущенных объектов.

Как объединить ответы деревьев

Регрессия: среднее числовых прогнозов

Если предсказываем оценку отзыва, три дерева могут выдать \(2\), \(4\) и \(3\) звезды. Ответ ансамбля — \((2+4+3)/3=3\). Для \(B\) деревьев с прогнозами \(T_b(x)\) на заказе \(x\) это записывается так:

\[\hat f(x)=\frac1B\sum_{b=1}^{B}T_b(x).\]

Сначала каждый заказ проходит по своему пути в каждом дереве, затем полученные числа усредняются. Среднее не может выйти за диапазон ответов деревьев. Поэтому обычный лес с листьями-средними, как и одиночное дерево, не умеет продолжать возрастающий тренд за пределы обучающих данных.

Классификация: голоса или вероятности

Для классов есть два распространённых способа объединения. В исходной схеме бэггинга деревья голосуют своими классами, побеждает большинство. Другой способ — усреднить вероятности из листьев и выбрать класс по полученному среднему. В scikit-learn 1.9.1 используется второй способ. Для негатива:

\[\hat p(x)=\frac1B\sum_{b=1}^{B}p_b(x),\]

где \(p_b(x)\) — доля негативных отзывов в листе дерева \(b\), куда пришёл заказ. Повторы бутстрэпа участвуют в этой доле. Для двух классов обычно выбирают негатив при вероятности выше \(0.5\); рабочий порог можно подобрать по цене ошибок.

Различие способов видно на условных ответах трёх деревьев для одного заказа:

ДеревоДоля негатива в листеКласс при пороге \(0.5\)
1\(6/10=0.6\)негатив
2\(3/5=0.6\)негатив
3\(1/10=0.1\)без негатива

По большинству голосов получится негатив: два дерева против одного. По среднему вероятностей получится \((0.6+0.6+0.1)/3\approx0.433\), то есть без негатива. Третье дерево дало сильную оценку в пользу своего класса, а первые два — пограничные; усреднение вероятностей это учитывает, голосование — нет. При чистых листьях ответы равны \(0\) или \(1\), и два способа совпадают, если одинаково разрешать ничью.

Однако среднее вероятностей ещё не означает хорошую калибровку: среди заказов с оценкой \(0.7\) негатив не обязан встречаться ровно в \(70\%\) случаев. Это отдельное свойство, которое проверяют на отложенных данных.

Почему усреднение помогает и где его предел

Представим несколько версий обучающей выборки. Для одного и того же нового заказа прогноз дерева то выше, то ниже. Этот разброс называют дисперсией (variance). Усреднение помогает, если отклонения разных деревьев хотя бы частично компенсируются. Если все деревья одновременно завышают оценку, среднее тоже её завысит.

Степень совместного изменения числовых прогнозов описывает корреляция (correlation). При корреляции, близкой к единице, деревья колеблются почти одинаково; при меньшей — в их ответах больше самостоятельной вариации. Здесь речь о прогнозах для фиксированного объекта при повторном обучении, а не о корреляции признаков и не просто о доле одинаковых классов на тесте.

Одна формула связывает размер ансамбля и эту зависимость. Пусть каждый прогноз имеет дисперсию \(s^2\), а попарная корреляция прогнозов равна \(\rho\). Тогда дисперсия их среднего:

\[\operatorname{Var}(\hat f(x))=\underbrace{\rho s^2}_{\text{общая часть разброса}}+\underbrace{\frac{1-\rho}{B}s^2}_{\text{часть, которую гасит усреднение}}.\]

Вывод формулы

Зафиксируем заказ \(x\) и для краткости обозначим прогноз дерева \(b\) через \(T_b=T_b(x)\). Деление суммы прогнозов на \(B\) уменьшает её дисперсию в \(B^2\) раз.

\[\operatorname{Var}(\hat f(x))=\frac{1}{B^2}\operatorname{Var}\left(\sum_{b=1}^{B}T_b\right).\]

Чтобы найти дисперсию суммы, раскроем квадрат суммы отклонений прогнозов от их средних. После усреднения каждый квадрат даёт дисперсию, а каждое произведение двух разных отклонений даёт ковариацию. Каждая пара встречается дважды, поэтому перед суммой по парам стоит \(2\).

\[\operatorname{Var}\left(\sum_{b=1}^{B}T_b\right)=\sum_{b=1}^{B}\operatorname{Var}(T_b)+2\sum_{i<j}\operatorname{Cov}(T_i,T_j).\]

У нас \(B\) дисперсий по \(s^2\) и \(\frac{B(B-1)}{2}\) разных пар. Ковариация каждой пары равна \(\rho s^2\), поскольку корреляция равна ковариации, делённой на произведение стандартных отклонений \(s\cdot s\). Подставим эти числа и упростим.

\[\begin{aligned} \operatorname{Var}(\hat f(x))&=\frac{B s^2+B(B-1)\rho s^2}{B^2}\\ &=\frac{s^2}{B}+\left(1-\frac{1}{B}\right)\rho s^2\\ &=\rho s^2+\frac{1-\rho}{B}s^2. \end{aligned}\]

Её удобно читать по двум слагаемым. Второе уменьшается с числом деревьев, первое остаётся. При независимых прогнозах \(\rho=0\) и дисперсия уменьшается в \(B\) раз. При одинаковых прогнозах \(\rho=1\), и любое число копий оставляет исходную дисперсию. Для промежуточного случая возьмём условные \(s^2=1\) и \(\rho=0.3\):

Число деревьев \(B\)Общая частьУсредняемая частьДисперсия среднего
\(1\)\(0.3\)\(0.7\)\(1\)
\(10\)\(0.3\)\(0.07\)\(0.37\)
\(100\)\(0.3\)\(0.007\)\(0.307\)
Очень много\(0.3\)стремится к нулюстремится к \(0.3\)

Первые деревья дают большой выигрыш, следующие всё меньший. Уменьшить оставшийся общий разброс простым добавлением деревьев не получится — нужно менять сами деревья. При этом формула описывает именно дисперсию числового прогноза, а не долю ошибок классификации: из \(0.307\) нельзя заключить, что лес ошибётся на \(30.7\%\) заказов.

Есть тонкость: бутстрэп-выборки и случайные решения при построении деревьев можно генерировать независимо. Но все деревья опираются на одну исходную историю заказов. Если в ней случайно недопредставлены дорогие покупки без негативных отзывов, это повлияет на весь лес. При фиксированной истории случайности деревьев независимы; при смене истории их прогнозы меняются совместно. Именно второй взгляд нужен для объяснения общего слагаемого.

Усреднение также не исправляет общую систематическую ошибку — смещение (bias). Если все деревья слишком просты и не замечают взаимодействие цены и задержки, их среднее не восстановит пропущенное правило. Поэтому бэггинг особенно полезен для сложных, неустойчивых деревьев. Фраза «бэггинг снижает дисперсию, почти не меняя смещение» — полезный ориентир; сам переход от одного дерева к обучению на бутстрэпе может изменить и смещение.

От бэггинга к случайному лесу

Почему бутстрэпа может быть недостаточно

Пусть к задержке и цене добавили число позиций и рейтинг продавца. Задержка — самый сильный признак: почти в каждой бутстрэп-выборке первый вопрос о ней выигрывает у остальных. Деревья различаются порогами и нижними ветвями, но верхняя структура у многих одинакова. Значит, они во многом повторяют друг друга.

Случайный лес вводит ещё один источник различий: в каждом узле случайно выбирает несколько признаков и ищет лучшее разбиение только среди них. Например, из четырёх доступных признаков разрешает два:

УзелСлучайно разрешеныЧто делает дерево
Корень дерева 1задержка, ценаИщет лучшие пороги по этим двум признакам
Корень дерева 2цена, рейтинг продавцаОбязано начать без задержки, даже если она полезнее
Левый ребёнок дерева 2задержка, число позицийСнова может использовать задержку: подмножество выбрано заново

Выбор признаков случаен, но выбор лучшего порога среди разрешённых признаков остаётся обычным жадным поиском. Подмножество выбирается заново для каждого узла; это не один фиксированный набор на всё дерево. Ни один признак не удаляется из данных навсегда.

Теперь деревья чаще начинают с разных вопросов. Отдельное дерево может стать хуже, зато ошибки ансамбля меньше совпадают. Число разрешённых признаков регулирует компромисс: слишком много — мало разнообразия, слишком мало — деревья часто не видят полезного признака и недообучаются. В нашем примере при выборе двух из четырёх задержка попадает в набор кандидатов с вероятностью \(1/2\); если из ста признаков полезен только один, столь сильное ограничение может навредить. Выбор числа признаков и связь силы деревьев с их зависимостью — центральная идея Breiman (2001).

Почему деревья глубокие, а число деревьев не заменяет регуляризацию

Лесу нужны деревья, способные находить сложные зависимости: их случайные отклонения будет сглаживать ансамбль. Поэтому обычно начинают с глубоких деревьев, часто без обрезки. Это не означает, что каждый лист должен содержать один объект. Увеличение минимального размера листа делает оценки менее шумными; глубину также можно ограничить, если это улучшает validation.

Добавление деревьев при неизменном рецепте обучения всё точнее приближает средний ответ этого рецепта. Поэтому по числу деревьев качество обычно выходит на плато, а не систематически ухудшается, как при продолжительном подгоне одной модели. Но ошибка на конкретной validation может колебаться и иногда вырасти. Сходимость не обещает ни монотонного улучшения, ни хорошего предельного качества: лес из деревьев, запоминающих шум, тоже может обобщать плохо.

Деревья леса не используют ответы друг друга и могут строиться параллельно. В бустинге следующее дерево исправляет текущий ансамбль, поэтому этапы зависят друг от друга; этот механизм разберём следующим. Для леса больше деревьев — прежде всего более устойчивое среднее, а цена — память, время обучения и время предсказания. При одинаковой глубине стоимость предсказания растёт примерно пропорционально числу деревьев.

Extra Trees: случайными становятся и пороги

Предельно случайные деревья (extremely randomized trees, Extra Trees) усиливают разнообразие ещё одним изменением. Для каждого разрешённого числового признака берут случайный порог между его минимумом и максимумом в узле, а затем выбирают лучший из полученных вопросов по обычному критерию. Например, вместо перебора всех порогов задержки пробуют один случайный порог; он может оказаться менее удачным, но соседние деревья выберут другие.

Это уменьшает работу по поиску порогов и обычно снижает зависимость между деревьями, ценой возможного роста смещения. Победитель определяется разметкой, поэтому Extra Trees не означает «полностью случайное дерево, которое не смотрит на целевую переменную». В исходном алгоритме Geurts et al. (2006) используют всю обучающую выборку для каждого дерева; в scikit-learn 1.9.1 тоже по умолчанию bootstrap=False. Обычной OOB-оценки тогда нет. Extra Trees полезно сравнить с лесом на своей валидации: универсального преимущества нет.

OOB: оценка по деревьям, не видевшим объект

Вернёмся к последнему столбцу таблицы бутстрэпа. Дерево 1 не обучалось на заказах 6, 9 и 10, поэтому их можно использовать для проверки этого дерева. Но нас интересует качество ансамбля. Для каждого исходного заказа соберём ответы только тех деревьев, в чьё обучение он не попал, усредним их и сравним с настоящей меткой. Так получается OOB-прогноз.

Для трёх выборок из таблицы наборы деревьев будут разными:

Проверяемый заказКакие деревья можно использоватьПочему
6только 1Деревья 2 и 3 видели этот заказ
72 и 3Дерево 1 видело этот заказ
101, 2 и 3Ни одно дерево не видело этот заказ
1ни одногоВсе три дерева видели этот заказ

Допустим, для заказа 7 два допустимых дерева дали \(0.2\) и \(0.6\). Его OOB-оценка негатива равна \(0.4\). По порогу \(0.5\) это «без негатива», хотя в исходном примере заказ 7 негативный: одна OOB-ошибка. Значения ответов здесь условные, они нужны для демонстрации усреднения.

Дальше считаем выбранную метрику по всем объектам с OOB-прогнозом. Не нужно отдельно усреднять ошибки одиночных деревьев: это была бы оценка одиночного дерева, а не ансамбля. При большом числе деревьев каждый объект проверяется примерно на \(36.8\%\) леса, если размер бутстрэпа равен исходной выборке. Например, для \(B=300\) ожидаем около \(110\) OOB-деревьев на объект. При трёх деревьях оценка заведомо ненадёжна, и у заказа 1 её вообще нет.

OOB позволяет получить внутреннюю оценку качества в ходе одного обучения леса. Для независимых объектов одного распределения это удобная альтернатива обычной кросс-валидации, но не её универсальная замена. Если заказы одного покупателя зависимы, исключение одной строки не исключает остальные заказы этого покупателя. Если предсказываем будущее по прошлому, случайный бутстрэп не соблюдает время. В этих случаях нужны групповые или временные разбиения из раздела о валидации.

Ещё одна граница: OOB исключает объект из обучения конкретного дерева, но не из предобработки, сделанной заранее на всей выборке. Особенно опасны отбор признаков по цели и target encoding. А если много раз выбирать параметры по лучшей OOB-метрике, её значение для победителя становится оптимистичным, как при любом подборе по validation. Итоговую проверку проводят на отдельном тесте.

Что можно узнать о важности признаков

Важность по перестановке

Лес сложнее прочитать, чем одно дерево. Сначала можно усреднить встроенные важности деревьев — уменьшения неоднородности (MDI) из предыдущего раздела. Но усреднение не убирает их смещения: они посчитаны на обучении и благоприятствуют признакам с большим числом возможных разбиений.

Важность по перестановке (permutation importance) задаёт другой вопрос: насколько уже обученной модели нужны правильные значения конкретного признака на новых данных? Для этого модель не переобучают:

  1. Измеряют качество на validation.
  2. Перемешивают значения одного столбца между заказами, оставляя остальные столбцы и метки на местах. Например, заказу с маленькой задержкой теперь достаётся задержка другого заказа.
  3. Снова измеряют качество. Ухудшение показывает, насколько модель опиралась на нарушенную связь.
  4. Повторяют с несколькими перестановками, чтобы уменьшить влияние случайного перемешивания.

Условный пример: лес ошибался на \(20\%\) заказов. После перестановки задержки средняя ошибка выросла до \(32\%\), после перестановки цены — до \(23\%\). По этой метрике важность задержки равна \(12\) процентным пунктам, цены — \(3\). Это не доли от общего качества: складываться в \(100\%\) они не обязаны. Если используем метрику, которую нужно увеличивать, например accuracy, берём падение метрики. Небольшая отрицательная важность возможна из-за случайности или потому, что признак мешает модели. Процедура и её ограничения описаны в документации scikit-learn.

Главная ловушка — взаимозаменяемые признаки. Если задержка записана и в днях, и в часах, лес может распределить использование между двумя столбцами. Тогда перестановка каждого отдельно даст небольшое ухудшение, хотя информация о задержке в целом полезна. Кроме того, перемешивание создаст невозможные сочетания: два часа и семь дней в одной строке. Для таких признаков полезно проверить совместную перестановку группы, используя одну перестановку строк для всех её столбцов, или сравнить модели с разными наборами признаков. Низкая отдельная важность не доказывает бесполезность информации; официальный пример показывает этот эффект на коррелированных признаках.

SHAP: объяснение одного прогноза

Перестановка оценивает изменение качества на выборке. SHAP (SHapley Additive exPlanations) решает другую задачу: раскладывает конкретный прогноз на базовый уровень и вклады признаков. Условно: базовый риск негатива \(0.3\), задержка добавила \(0.2\), рейтинг продавца убавил \(0.1\), остальные вклады нулевые — получаем \(0.4\). Такие числа имеют смысл только при указанной шкале объясняемого выхода: вероятность, логит или другой выход модели.

Для деревьев существуют специальные алгоритмы TreeSHAP, позволяющие вычислять такие вклады эффективно. Результат зависит от фоновых данных и способа учитывать зависимые признаки. Это объяснение поведения модели, а не доказательство причинного влияния: вклад задержки не означает, что сокращение доставки на день изменит исход именно на такую величину. Основная идея SHAP — в Lundberg & Lee (2017), алгоритмы для деревьев — в Lundberg et al. (2018).

На практике

Какие параметры за что отвечают

Параметры удобнее выбирать по механизму действия. Сначала нужны корректное разбиение данных и метрика. Затем сравнивают размер листа, число доступных признаков и при необходимости глубину. Число деревьев увеличивают до достаточно устойчивой оценки с учётом времени и памяти. Это порядок работы для первого эксперимента, а не обязательный алгоритм подбора.

ПараметрЧто меняетНа что смотреть
n_estimatorsЧисло деревьевСтабилизацию validation или OOB и стоимость предсказания; больше деревьев не исправит неудачный рецепт
max_featuresЧисло кандидатов-признаков в каждом узлеБаланс разнообразия и качества отдельного дерева
min_samples_leaf, max_depthСложность каждого дереваНе слишком ли шумные листья и не потеряны ли полезные взаимодействия
bootstrap, max_samplesИспользование бутстрэпа и число выбираемых строкМеньшая выборка ускоряет обучение, но может ослабить деревья; доля OOB при этом меняется
class_weightВес объектов разных классовМеняются разбиения и вероятности; это не то же самое, что сдвинуть порог готовой модели

В scikit-learn 1.9.1 у RandomForestClassifier по умолчанию max_features="sqrt": рассматривается целая часть квадратного корня из числа признаков, минимум один. У RandomForestRegressor значение 1.0 означает все признаки, то есть по этому механизму получается обычный бэггинг деревьев. Это различие реализаций классификации и регрессии, а не свойство любого случайного леса. Если среди выбранных признаков невозможно получить допустимое разбиение, scikit-learn может проверить дополнительные.

Код обучения и оценки

Ниже признаки уже числовые: задержка, цена, число позиций и рейтинг продавца; метки — \(0\) и \(1\). X_train, X_val и соответствующие метки получены заранее корректным разбиением. OOB дополняет validation, а отдельный test остаётся для финальной проверки. Значения параметров — пример настройки, а не готовый оптимум.

from sklearn.ensemble import RandomForestClassifier
from sklearn.inspection import permutation_importance
from sklearn.metrics import roc_auc_score

forest = RandomForestClassifier(
    n_estimators=300,
    max_features="sqrt",
    min_samples_leaf=3,
    bootstrap=True,
    oob_score=True,
    random_state=42,
    n_jobs=1,
)
forest.fit(X_train, y_train)

# Столбец вероятности класса 1 находим по classes_.
pos = list(forest.classes_).index(1)
p_val = forest.predict_proba(X_val)[:, pos]
print("Validation ROC-AUC:", roc_auc_score(y_val, p_val))
print("OOB accuracy:", forest.oob_score_)

# Здесь важность — падение ROC-AUC, а не рост доли ошибок.
importance = permutation_importance(
    forest, X_val, y_val,
    scoring="roc_auc", n_repeats=5, random_state=42, n_jobs=1,
)
for name, mean, std in zip(
    ["delay_days", "price_k", "n_items", "seller_rating"],
    importance.importances_mean,
    importance.importances_std,
):
    print(name, round(mean, 3), round(std, 3))

Код сверен с документацией scikit-learn 1.9.1; обучение и перестановки не запускались. oob_score_ при oob_score=True по умолчанию содержит accuracy: её нельзя напрямую сравнивать с напечатанным ROC-AUC. Для OOB ROC-AUC нужны вероятности из oob_decision_function_, а при малом числе деревьев нужно также проверить, что у каждого объекта есть допустимый OOB-прогноз. Выбор метрики особенно важен при дисбалансе классов.

Масштабировать числовые признаки для обычного леса не требуется. Категории нужно закодировать; произвольные номера категорий навязывают порядок, как и в одиночном дереве. Разреженный TF-IDF технически допустим, но большое число признаков и редкие слова могут сделать поиск хороших вопросов неэффективным: для текста стоит иметь линейную модель как отдельный бейзлайн. Лес особенно удобен как стартовая модель по табличным признакам заказа или по компактному набору признаков текста.
