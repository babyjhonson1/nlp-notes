XGBoost, LightGBM и CatBoost строят ансамбль из деревьев, которые последовательно поправляют прогноз. Различия особенно заметны в том, как оценить разбиение, где искать следующие разбиения и что делать с категориями. На тех же заказах разберём оценку разбиения XGBoost, поиск по гистограммам LightGBM и кодирование продавца в CatBoost. Эти механизмы помогают понять, какой параметр менять, когда дерево слишком сложное, обучение долгое или качество на валидации падает.

XGBoost — сколько стоит разбиение

В предыдущем примере дерево выбирало разбиение по квадратичной ошибке на псевдоостатках. Когда листья были готовы, их значения пересчитывались по исходной log-loss. В XGBoost кривизна потери участвует уже в выборе разбиения. Это позволяет оценить, насколько улучшится приближённая целевая функция, если заменить один лист двумя.

Вес листа и выигрыш от разделения

Пусть \(F_i\) — текущий логит заказа, \(p_i=\sigma(F_i)\) — оценка вероятности, \(y_i\) — метка. Для log-loss градиент \(g_i=p_i-y_i\) имеет знак, противоположный псевдоостатку, а кривизна \(h_i=p_i(1-p_i)\) совпадает со знаменателем шага Ньютона для одного заказа. Для всех заказов в листе \(R\) достаточно двух сумм.

\[G_R=\sum_{i\in R}g_i,\qquad H_R=\sum_{i\in R}h_i,\qquad w_R^*=-\frac{G_R}{H_R+\lambda}.\]

Здесь \(w_R^*\) — поправка листа до умножения на шаг обучения. При \(\lambda=0\) получаем шаг Ньютона из предыдущего раздела. Чем больше штраф за квадрат веса \(\lambda\), тем меньше модуль поправки при тех же \(G_R\) и \(H_R\). Если заменить родителя \(P\) двумя листьями \(L,R\), выигрыш (gain) в нормировке статьи равен

\[\operatorname{Gain}=\frac12\left(\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{G_P^2}{H_P+\lambda}\right)-\gamma.\]

Первые два слагаемых дают выигрыш от отдельных поправок в детях. Третье вычитает выигрыш, который уже давала общая поправка родителя. Штраф \(\gamma\) платим за один добавленный лист. В этой постановке разбиение улучшает цель, когда итоговый gain положителен. См. Chen и Guestrin (2016), §2.

Вывод веса листа и gain

Один лист прибавляет одинаковое число \(w\) к логитам всех заказов в нём. Разложим потерю каждого заказа по Тейлору около текущего логита и отбросим постоянную часть. Остаются \(g_iw+\tfrac12h_iw^2\). После суммирования и добавления штрафа за вес получаем функцию одного числа.

\[Q_R(w)=G_Rw+\tfrac12(H_R+\lambda)w^2.\]

При \(H_R+\lambda>0\) это парабола с минимумом там, где \(G_R+(H_R+\lambda)w=0\). Отсюда \(w_R^*=-G_R/(H_R+\lambda)\), а после подстановки \(Q_R(w_R^*)=-G_R^2/[2(H_R+\lambda)]\). Вычитаем минимальную потерю двух детей из минимальной потери родителя и учитываем стоимость дополнительного листа \(\gamma\). Эта формула оценивает изменение приближённой цели на текущем шаге.

Вернёмся к восьми заказам, у которых начальная вероятность \(0.5\). Среди четырёх заказов с небольшой задержкой один негативный отзыв, среди четырёх с большой — три. Для разделения по задержке получаются \(G_L=1\), \(G_R=-1\) и \(H_L=H_R=1\). У родителя градиенты взаимно погашаются. При \(\lambda=1\) веса листьев равны \(-0.5\) и \(+0.5\). Выигрыш до штрафа равен \(0.5\), поэтому при \(\gamma=0.3\) остаётся \(0.2\).

Допустимое разбиение должно пройти и проверку min_child_weight. Она задаёт минимальную сумму \(h_i\) в каждом ребёнке. При \(p_i=0.5\) четыре заказа дают \(H=1\), а при \(p_i=0.99\) те же четыре дают \(H=0.0396\). Поэтому один порог может разрешить первый лист и отвергнуть второй, хотя размер групп одинаков. См. параметры XGBoost.

Куда идёт заказ без значения признака

Если у заказа неизвестна задержка, при оценке порога XGBoost проверяет оба варианта. В одном все пропуски добавляются к левому ребёнку, в другом к правому. Выбирается выгоднейший вариант и сохраняется направление для новых заказов с пропуском. Например, скроем задержку у первого заказа с меткой \(0\). При \(\lambda=1\) выигрыш до штрафа будет \(0.500\) при отправке пропуска влево и около \(0.127\) при отправке вправо. В первом случае группа с низким риском остаётся более однородной по градиентам. См. Chen и Guestrin (2016), §3.4.

LightGBM — поиск по гистограммам и рост по листьям

Как уменьшить число порогов

При поиске разбиения достаточно знать суммы градиентов и кривизн по обе стороны порога. Гистограммный метод (histogram-based learning) сначала группирует значения признака в интервалы, или бины, а затем перебирает только границы бинов. Для каждого бина в узле накапливаются \(G\) и \(H\).

Для примера дадим восьми заказам задержки от одного до восьми дней по порядку. Граница в четыре дня сохраняет прежнее разделение. Объединим задержки по две и посчитаем гистограмму для начальных вероятностей \(0.5\).

Задержка, дниМеткиСумма \(G\)Сумма \(H\)
1–2\(0,0\)\(1\)\(0.5\)
3–4\(0,1\)\(0\)\(0.5\)
5–6\(0,1\)\(0\)\(0.5\)
7–8\(1,1\)\(-1\)\(0.5\)

Для границы после четвёртого дня слева складываем первые два бина, справа остальные. Получаем те же суммы \(G_L=1\), \(G_R=-1\) и \(H_L=H_R=1\). После заполнения гистограммы поиск проходит по бинам вместо всех различных значений. Если полезный порог оказался внутри бина, такой порог станет недоступен. Для ускорения LightGBM также может построить гистограмму меньшего ребёнка и получить гистограмму второго вычитанием из родительской. Гистограммы применяются и в других библиотеках, в том числе в режиме hist XGBoost. См. LightGBM 4.6.0 и параметры XGBoost.

Какой лист делить дальше

LightGBM на каждом шаге выбирает лист с наибольшим допустимым выигрышем (leaf-wise growth). Допустим, после корня в двух листьях лучшие выигрыши равны \(0.8\) и \(0.2\). Первый разделится. Если у одного из новых детей выигрыш \(0.5\), следующий шаг снова пойдёт в эту ветку, поскольку \(0.5>0.2\). При росте по уровням (depth-wise growth) раньше рассмотрели бы оставшийся лист меньшей глубины.

При одном бюджете листьев такой рост может направить больше разбиений туда, где они дают большую пользу, и создать глубокую ветку только для небольшой группы заказов. num_leaves ограничивает общее число листьев, max_depth — длину пути, а min_child_samples помогает избегать слишком малых листьев. Даже при заданной глубине LightGBM сохраняет порядок роста по листьям. См. описание роста деревьев.

Какие строки и столбцы можно обработать компактнее

GOSS (Gradient-based One-Side Sampling) сохраняет объекты с большими по модулю градиентами. Из остальных берёт случайную подвыборку и увеличивает вес оставшихся объектов этой группы. Так при оценке разбиений обрабатывается меньше строк, а заказы с сильным сигналом на поправку сохраняются. В LightGBM 4.6.0 это режим data_sample_strategy="goss". См. параметры LightGBM.

EFB (Exclusive Feature Bundling) сокращает число столбцов. Например, у one-hot признаков «доставка курьером» и «самовывоз» только один столбец активен в каждой строке. Их ненулевым бинам назначаются разные диапазоны номеров в одном объединённом столбце. По диапазону можно определить исходный признак. Когда признаки часто активны вместе, такая упаковка с одним значением на строку теряет информацию. См. Ke et al. (2017).

Категориальный признак можно подать в LightGBM напрямую. Тогда дерево ищет разбиение на группы категорий по статистикам текущего узла. В CatBoost история продавца может стать отдельным числовым признаком. См. категориальные разбиения LightGBM.

CatBoost — категории и порядок наблюдений

Как кодировать продавца по прошлым наблюдениям

У магазина много продавцов, а заказов у части из них мало. Вместо отдельного столбца на продавца можно дать дереву историческую долю негативных отзывов этого продавца. Это кодирование по цели (target encoding). Если посчитать долю по всем обучающим заказам и сразу подать её обратно в те же строки, каждая строка повлияет на собственный признак. Для продавца с одним заказом сырая доля совпадёт с меткой заказа.

Упорядоченная целевая статистика (ordered target statistic) берёт для каждого заказа только более ранние строки того же продавца в выбранной перестановке обучающих данных. Для редкого продавца долю сглаживают к базовому значению \(p_0\). В учебном варианте \(s\) — число негативных отзывов в доступном префиксе, \(n\) — число заказов, \(a\) — вес базового значения.

\[\operatorname{TS}=\frac{s+a p_0}{n+a}.\]

Возьмём перестановку заказов 4, 2, 5, 6 и метки из предыдущего раздела. У заказов 4, 2 и 6 продавец А, у заказа 5 — Б. При \(p_0=0.5\) и \(a=2\) первый заказ продавца А получает \(0.5\). Ко второму заказу А уже известен один негативный отзыв, поэтому код равен \((1+1)/(1+2)=2/3\). Его собственная метка станет доступна только следующим строкам. Для нового заказа статистику можно взять по всем доступным обучающим наблюдениям продавца.

Перестановка задаёт учебный порядок внутри train. Если в задаче важно реальное время, история признаков и границы train/validation всё равно должны учитывать момент прогноза. В библиотеке есть несколько видов статистик категорий и режимы обработки малых категорий. Здесь показана одна формула, которая объясняет принцип исключения собственной метки. См. Prokhorenkova et al. (2018), §3.

Как порядок помогает при расчёте градиента

Даже с безопасными признаками на следующем шаге бустинга градиент вычисляется в точке, которую предсказал текущий ансамбль. В обычном обучении этот ансамбль уже использовал метку данного заказа. Для нового заказа такой зависимости нет. Разницу в распределениях предсказаний на обучающих и новых объектах авторы называют сдвигом предсказаний (prediction shift).

В схеме упорядоченного бустинга (ordered boosting) для градиента текущей строки используют предсказание вспомогательной модели, которая обучалась на предыдущих строках перестановки. Метка текущей строки нужна для самой производной, но её ещё не использовали для получения предсказания, в котором берут производную. CatBoost переиспользует структуру деревьев для вспомогательных моделей. Упорядоченное кодирование определяет значение входного признака, а упорядоченный бустинг — прогноз для расчёта очередного градиента. У библиотеки также есть режим Plain. См. Prokhorenkova et al. (2018), §4–5 и параметр boosting_type.

Почему деревья симметричные

В политике SymmetricTree один и тот же вопрос применяется во всех узлах данного уровня. Если на первом уровне спрашиваем о задержке, а на втором о цене, вопрос о цене задаётся в обеих ветках. Последовательность ответов кодирует номер листа, поэтому вычисление прогноза сводится к проверкам по уровням и обращению к таблице весов. Цена такой структуры — меньше гибкости, когда в разных ветках полезны разные признаки. См. политики роста CatBoost.

На практике

Что сравнивать на своей задаче

Начните с общей валидации и метрики. Для одного небольшого шага обучения подберите число деревьев по ранней остановке. Затем сравните ограничения на сложность дерева и снова проверьте, сколько итераций нужно. После этого имеет смысл проверить подвыборки и усиление регуляризации. При временной задаче и признаки, и валидация должны соответствовать информации, доступной до прогноза.

Деревья остаются сильным исходным вариантом для табличных признаков заказа. В сравнении Grinsztajn, Oyallon и Varoquaux на \(45\) табличных наборах классические деревья хорошо показали себя против изученных нейросетей на задачах порядка \(10\,000\) строк. Этот результат относится к их наборам и моделям. При наличии текста, изображений или истории действий меняется и вход задачи. Например, можно подать эмбеддинги вместе с табличными признаками в бустинг и сравнить с нейросетевым ранкером на общей валидации. См. Grinsztajn et al. (2022).

Важности признаков тоже сравнивают по одной шкале. Split count считает число разбиений, а gain учитывает, сколько выиграли эти разбиения. Например, в LightGBM gain — сумма выигрышей, в XGBoost gain — среднее, а total_gain — сумма. Признак с одним сильным разбиением может уступить по частоте и выиграть по суммарному эффекту. SHAP раскладывает конкретный прогноз. Для сравнения по выборке можно усреднить модули вкладов по отложенным заказам. См. LightGBM, XGBoost и ручной расчёт SHAP.

LightGBM и CatBoost на одной валидации

Ниже \(X_{\text{train}}\) и \(X_{\text{val}}\) — таблицы pandas с числовыми признаками заказа и строковым seller_id. Пропуск в ID можно заранее представить отдельной строковой категорией. В LightGBM создаём тип категорий по train и применяем его к validation. CatBoost получает исходные строки и имя категориального столбца. Оба примера используют log-loss и одну отложенную выборку. Настройки приведены для обычного набора заказов и ранней остановки.

import lightgbm as lgb
from catboost import CatBoostClassifier

train_lgb, val_lgb = X_train.copy(), X_val.copy()
train_lgb["seller_id"] = X_train["seller_id"].astype("category")
val_lgb["seller_id"] = X_val["seller_id"].astype(train_lgb["seller_id"].dtype)

light = lgb.LGBMClassifier(
    n_estimators=1000, learning_rate=0.05, num_leaves=15,
    min_child_samples=20, n_jobs=1, random_state=42,
)
light.fit(
    train_lgb, y_train, eval_set=[(val_lgb, y_val)],
    eval_metric="binary_logloss", callbacks=[lgb.early_stopping(50)],
)

cat = CatBoostClassifier(
    iterations=1000, learning_rate=0.05, depth=4,
    loss_function="Logloss", eval_metric="Logloss",
    thread_count=1, random_seed=42, verbose=False, allow_writing_files=False,
)
cat.fit(
    X_train, y_train, cat_features=["seller_id"],
    eval_set=(X_val, y_val), early_stopping_rounds=50, use_best_model=True,
)

У LightGBM продавец, которого не было в train, после приведения типа попадает в пропуски. В CatBoost новая категория обрабатывается по правилам модели для неизвестных категорий. После подбора на validation итоговое качество оценивают на отдельном тесте. API сверены для LightGBM 4.6.0 и CatBoost 1.2.8. См. LightGBM и CatBoost.
