Ошибку на новых данных оценивают по отложенной выборке, и эта оценка честна, только если отложенные данные не участвовали ни в одном решении: ни в обучении, ни в предобработке, ни в выборе модели. На практике оценку портят три вещи: разбиение, которое не похоже на будущее использование модели; выбор лучшей из многих конфигураций по той же выборке, на которой о ней отчитываются; утечки. Ниже — схемы разбиения и вопрос, на который отвечает каждая, смещение после выбора модели и вложенная кросс-валидация, утечки на текстах, подбор гиперпараметров и сравнение двух моделей с учётом шума маленького теста. Сквозной пример — классификатор негативных отзывов о товарах.

Hold-out и k-fold: что оценивает кросс-валидация

Hold-out — одно разбиение на train, validation и test: модель обучают на первой части, конфигурацию выбирают по второй, итог сообщают по третьей. Цена — шум. Доля ошибок на \(n\) независимых примерах имеет стандартную ошибку \(\sqrt{p(1-p)/n}\): при точности \(0.85\) на \(200\) отзывах \(95\%\)-интервал — примерно \(\pm4.9\) процентного пункта. Разница в один-два пункта на таком тесте ничего не значит.

k-fold кросс-валидация (cross-validation, CV) делит данные на \(K\) частей; каждая по очереди служит validation, модель обучается на остальных, оценки усредняются. Каждый пример используется для оценки ровно один раз, поэтому дисперсия ниже, чем у одного hold-out того же размера. Три уточнения, о которых спрашивают:

  • Что именно оценивается. Каждая модель обучена на доле \((K-1)/K\) данных, поэтому CV оценивает ошибку процедуры обучения на чуть меньшей выборке — с небольшим пессимизмом относительно финальной модели на всех данных. Bates, Hastie, Tibshirani (2023) показали для линейной регрессии: CV оценивает среднюю ошибку процедуры по воображаемым обучающим выборкам из той же совокупности, а не ошибку конкретной обученной модели.
  • Выбор \(K\). Обычный компромисс — \(5\) или \(10\) (ESL, гл. 7.10): меньше \(K\) — сильнее пессимизм из-за малой обучающей части, больше — дороже. Leave-one-out (\(K=n\)) почти несмещён, но требует \(n\) обучений и даёт оценку с заметной дисперсией: обучающие выборки почти совпадают. Исключение — линейные сглаживатели вроде линейной и ridge-регрессии: для них LOO считается по одному обучению, \(\frac1n\sum_i\big(\frac{y_i-\hat f(x_i)}{1-S_{ii}}\big)^2\), где \(S_{ii}\) — диагональ матрицы, переводящей \(y\) в прогнозы.
  • Интервал по фолдам. Оценки фолдов зависимы — у них пересекаются обучающие части, — поэтому стандартное отклонение по фолдам, делённое на \(\sqrt K\), даёт слишком узкий интервал. Универсальной несмещённой оценки дисперсии k-fold CV не существует (Bengio & Grandvalet, 2004); Bates et al. предлагают для интервала вложенную CV.

Разбиение задаёт вопрос: стратифицированное, групповое, временное

Разбиение должно имитировать то, как модель встретит новые данные. Один и тот же классификатор отзывов отвечает на разные вопросы: «как он работает на новых отзывах о знакомых товарах», «на товарах, которых не было в обучении», «в следующем месяце». Каждому вопросу соответствует своя схема, и оценки по ним законно различаются.

Временное разбиение обучает только на прошлом; параметр gap выбрасывает примеры между обучением и проверкой — это нужно, когда метка приходит с задержкой или признаки считаются по скользящему окну и иначе захватили бы период проверки. TimeSeriesSplit работает по позициям строк и не сортирует данные: таблицу нужно заранее упорядочить по времени.

Если групповое или временное разбиение даёт заметно худшую оценку, чем случайное, это не недостаток схемы: случайное разбиение отвечало на более лёгкий вопрос, чем тот, что встретится в эксплуатации.

Выбор модели смещает оценку: test и вложенная CV

Пусть перебрали \(m\) конфигураций и взяли лучшую по validation. Даже если все они одинаково хороши, минимум из шумных оценок меньше истинной ошибки. При независимых ошибках оценок со стандартным отклонением \(s\) и равных истинных ошибках \(R\)

\[\mathbb E\min_{j\le m}\hat R_j=R-s\,\mathbb E\max_{j\le m}Z_j,\qquad Z_j\sim\mathcal N(0,1)\ \text{независимы}.\]

Для \(m=20\) математическое ожидание максимума — около \(1.87\). Validation из \(500\) отзывов при истинной ошибке \(20\%\) даёт \(s\approx1.8\) п. п., и лучшая из двадцати равных конфигураций в среднем покажет около \(16.7\%\). На одной и той же validation ошибки конфигураций коррелированы, и смещение меньше, но направление то же: чем больше перебор, тем оптимистичнее оценка победителя. Это смещение отбора (selection bias); его же даёт ранняя остановка бустинга по validation, если по той же выборке сообщать итог.

Два лекарства:

  • Отдельный test, на который смотрят один раз, после всех решений. Каждое решение, принятое по test (ещё одна попытка, другой порог, «а если убрать этот признак»), превращает его в validation. Так переобучаются на публичном лидерборде соревнований.
  • Вложенная кросс-валидация (nested CV), когда данных мало. Внутренний цикл на обучающей части внешнего фолда выполняет весь подбор; внешний оценивает процедуру «подбор + обучение» на фолде, который подбор не видел. Это оценка процедуры, а не конкретного набора гиперпараметров: во внешних фолдах могут выиграть разные конфигурации, и это нормально. Финальную модель получают, запустив тот же подбор на всех данных. Стоимость — \(K_{\text{outer}}\cdot K_{\text{inner}}\cdot m\) обучений.

Varma & Simon (2006) и Cawley & Talbot (2010) показали эмпирически, что CV-оценка выбранной по той же CV модели бывает заметно оптимистична, особенно на малых выборках и при большом переборе.

Утечки

Утечка (data leakage) — попадание в обучение, предобработку или выбор модели информации, которой не будет в момент предсказания, или информации из оценочной части. Признаки: подозрительно высокое качество, один признак доминирует по важности, качество падает после выкатки.

Отбор признаков до кросс-валидации

Классический пример из ESL (гл. 7.10.2): \(50\) объектов двух равных классов, \(5000\) гауссовых признаков, не зависящих от метки, так что истинная ошибка любого классификатора — \(50\%\). Если сначала отобрать по всей выборке \(100\) признаков с наибольшей корреляцией с меткой, а затем оценить 1-NN пятикратной CV, средняя CV-ошибка по 50 симуляциям получается около \(3\%\). Отбор уже видел метки будущих validation-фолдов и нашёл признаки, случайно с ними согласованные. Правильно — отбирать признаки заново внутри каждого фолда, только по его обучающей части; тогда оценка возвращается к \(50\%\). Наше повторение на стандартной библиотеке (10 прогонов) даёт около \(2\%\) и \(54\%\).

ESL там же отмечает границу: предварительный отбор без учителя — например, по дисперсии признака, без взгляда на метки — можно делать до разбиения. Опасна обработка, которая использует метки.

Подбор гиперпараметров

Сетка (grid search) перебирает декартово произведение значений: число обучений растёт экспоненциально с числом гиперпараметров. Случайный поиск (random search) при том же бюджете обычно не хуже, а часто лучше. Bergstra & Bengio (2012) объясняют это низкой эффективной размерностью: качество заметно зависит лишь от немногих гиперпараметров, и заранее неизвестно, от каких. Сетка \(3\times3\) из девяти точек проверяет только три значения важного параметра; девять случайных точек — девять разных значений. Для параметров масштаба (\(C\), learning rate, \(\lambda\)) значения берут по логарифмической шкале.

Байесовская оптимизация строит суррогатную модель метрики как функции гиперпараметров (гауссовский процесс или TPE, как в Optuna) и выбирает следующую точку по функции приобретения (acquisition function), например ожидаемому улучшению (expected improvement). Она окупается, когда одно обучение дорого и бюджет — десятки запусков. Отдельная идея — successive halving: дать многим конфигурациям малый бюджет (часть данных, мало деревьев или эпох) и продолжать обучение только лучшей доли. Какой бы метод ни использовался, выбор идёт по validation, и смещение из предыдущего блока остаётся.

Сравнение двух моделей

Модели A и B оценены на одном тесте — значит, сравнение парное: важны только примеры, где модели расходятся. Пусть на \(1000\) отзывах A верна, а B ошибается в \(b=30\) случаях, обратное — в \(c=15\); точности \(0.870\) и \(0.855\). Отдельные \(95\%\)-интервалы точностей (\(\pm2.1\) и \(\pm2.2\) п. п.) пересекаются, но вывод «различия нет» отсюда не следует: интервалы не учитывают, что ошибки на общих примерах совпадают.

Тест McNemar. При гипотезе равного качества каждый из \(b+c\) примеров с расхождением с вероятностью \(1/2\) оказывается в пользу A, то есть \(b\sim\operatorname{Bin}(b+c,1/2)\). Точное двустороннее p-значение здесь \(0.036\); приближение \(\chi^2_1\) с поправкой на непрерывность, \(\frac{(\lvert b-c\rvert-1)^2}{b+c}=4.36\), даёт \(0.037\). Остальные \(955\) примеров, на которых модели согласны, на вывод не влияют.

Парный бутстрэп работает для любой метрики, в том числе неаддитивной (F1, ROC-AUC): примеры теста выбирают с возвращением, на каждой псевдовыборке считают метрику обеих моделей и их разность, интервал берут по перцентилям. Для примера выше \(95\%\)-интервал разности точностей — примерно \([0.002;\,0.028]\): ноль не входит. Бутстрэп по примерам предполагает их независимость; если отзывы сгруппированы по товарам, выбирают с возвращением товары целиком (кластерный бутстрэп).

Сравнение по фолдам CV обычным парным t-тестом слишком либерально: оценки фолдов зависимы. Dietterich (1998) рекомендует McNemar на отдельном тесте или схему \(5\times2\) CV; Nadeau & Bengio (2003) — поправленный t-тест с учётом пересечения обучающих выборок.

На практике

McNemar и парный бутстрэп без библиотек

Код воспроизводит числа примера: \(1000\) отзывов, \(840\) — обе модели правы, \(30\) — права только A, \(15\) — только B, \(115\) — обе ошибаются.

import random
from math import comb

def mcnemar_exact(b, c):
    n, k = b + c, min(b, c)
    tail = sum(comb(n, i) for i in range(k + 1)) / 2**n
    return min(1.0, 2 * tail)

def paired_bootstrap(correct_a, correct_b, n_boot=2000, seed=0):
    rng, n = random.Random(seed), len(correct_a)
    diffs = []
    for _ in range(n_boot):
        idx = [rng.randrange(n) for _ in range(n)]
        diffs.append(sum(correct_a[i] - correct_b[i] for i in idx) / n)
    diffs.sort()
    return diffs[int(0.025 * n_boot)], diffs[int(0.975 * n_boot) - 1]

a = [1] * 840 + [1] * 30 + [0] * 15 + [0] * 115
b = [1] * 840 + [0] * 30 + [1] * 15 + [0] * 115
print(round(mcnemar_exact(30, 15), 3))
print([round(x, 3) for x in paired_bootstrap(a, b)])
# 0.036
# [0.002, 0.028]

Вложенная CV с групповым разбиением

TF-IDF и логистическая регрессия в одном Pipeline, разбиение по товарам на обоих уровнях. Внешний цикл записан явно, чтобы было видно, что подбор видит только обучающую часть внешнего фолда.

import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import f1_score
from sklearn.model_selection import GridSearchCV, GroupKFold
from sklearn.pipeline import make_pipeline

# texts, y, product_ids — np.array одинаковой длины
pipe = make_pipeline(TfidfVectorizer(ngram_range=(1, 2), min_df=2),
                     LogisticRegression(max_iter=1000))
search = GridSearchCV(pipe, {"logisticregression__C": [0.1, 1, 10, 100]},
                      cv=GroupKFold(n_splits=5), scoring="f1")

outer_scores = []
for train, test in GroupKFold(n_splits=5).split(texts, y, groups=product_ids):
    search.fit(texts[train], y[train], groups=product_ids[train])
    outer_scores.append(f1_score(y[test], search.predict(texts[test])))
print(np.mean(outer_scores), search.best_params_)  # best_params_ последнего фолда

search.fit(texts, y, groups=product_ids)  # финальная модель: тот же подбор на всех данных

Код сверен с документацией scikit-learn 1.9.1, но не запускался. Тихие ошибки:

  • cv=5 во внутреннем поиске означает StratifiedKFold без групп и без перемешивания: внешний цикл честный, а подбор внутри него — с утечкой по товарам.
  • KFold без shuffle на таблице, отсортированной по классу или дате, даёт фолды из одного класса или одного периода.
  • TfidfVectorizer или отбор признаков, обученные до cross_val_score, переносят статистики validation в признаки.
