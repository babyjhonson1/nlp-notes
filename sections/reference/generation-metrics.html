Качество ответа нельзя свести к сходству с одной эталонной строкой. Ответ может быть верным, но не подтверждённым предоставленным контекстом; полностью подтверждённым, но неполным; содержать правильные факты с неправильными ссылками. Здесь определены метрики фактического ответа, опоры на источники и цитирования, нужные для оценки RAG. Для каждой фиксируем единицу разметки, знаменатель и обработку пустого ответа, чтобы одинаковое название не скрывало разные расчёты.

Что размечается

Для одного вопроса обозначим ответ через \(a\), реально переданный генератору контекст — через \(C\), проверенный эталон с допустимыми вариантами — через \(y\). Множество \(A(a)\) содержит атомарные проверяемые утверждения ответа. «Нужно обратиться в поддержку, и доступ восстановят сразу» — два утверждения: первое может быть верным, второе — нет. Условия и отрицания сохраняют внутри соответствующего утверждения.

Пример условный и продолжает документацию сервиса. Эталон требует три факта: обращение через форму с проверкой личности по телефону; подтверждение корпоративного запроса администратором; срок до двух рабочих дней после завершения всех проверок. Последний факт нельзя заменить фразой «два дня»: потеря единицы времени или начала отсчёта меняет условие.

Фиксируем одинаковую гранулярность утверждений для всех систем. Служебные фразы и выражения вежливости в \(A(a)\) не включаем. Дубликаты одного факта объединяем: повторение подтверждённой фразы не должно повышать оценку. Разметчик отдельно отмечает противоречие источнику и отсутствие сведений; оба случая не получают балл подтверждения, но требуют разной диагностики.

Подтверждённость контекстом: faithfulness

Подтверждённость контекстом (faithfulness) — доля утверждений ответа, выводимых из предоставленных источников. Пусть \(e(c,C)\) равен единице, если контекст достаточно подтверждает утверждение \(c\) со всеми его условиями, и нулю иначе. Тогда при непустом \(A(a)\):

\[\operatorname{Faithfulness}(a,C)=\frac{1}{|A(a)|}\sum_{c\in A(a)} e(c,C).\]

Если ответ содержит три утверждения, а контекст подтверждает два, оценка равна \(2/3\). Число не показывает полноту: одно верное предложение может получить единицу и пропустить почти весь вопрос. Ответ, верный по внешнему эталону, но отсутствующий в \(C\), тоже не получает подтверждения. И наоборот, пересказ устаревшего источника может быть faithful и неверным по действующим правилам.

Схема «выделить утверждения → проверить поддержку → усреднить» используется в RAGAs. Конкретный результат зависит от выделения утверждений, судьи и его инструкции; совпадение названия метрики не гарантирует совпадение реализации. При отсутствии утверждений возвращаем «не определено», а не единицу; долю таких ответов и корректность отказов учитываем отдельно.

Правильность и полнота ответа

Правильность ответа (answer correctness) требует сравнения с проверенным эталоном \(y\), а не только с найденным контекстом. Единственной стандартной формулы под этим названием нет. Для основной оценки зададим бинарную рубрику: \(z_q=1\), если ответ покрывает все обязательные факты вопроса, не содержит существенных ошибок и выполняет заданные требования; иначе \(z_q=0\). На множестве вопросов \(Q\):

\[\operatorname{Correctness}(Q)=\frac{1}{|Q|}\sum_{q\in Q}z_q.\]

Для вопроса без ответа в зафиксированном корпусе рубрика может требовать корректного отказа; для ответимого вопроса отказ считается неуспехом. Частично ответимый вопрос требует отдельной рубрики: сообщить подтверждённую часть и явно назвать пробел. Рубрику выбирают до сравнения систем.

Для диагностики частичных ответов полезна фактическая F1 (fact-level F1). Пусть \(G(y)\) — множество обязательных фактов эталона, а \(M\) — число семантически согласованных пар между уникальными утверждениями \(A(a)\) и фактами \(G(y)\). Соответствие задаётся разметкой, один к одному; это не буквальное пересечение строк.

\[P_{\mathrm{fact}}=\frac{M}{|A(a)|},\qquad R_{\mathrm{fact}}=\frac{M}{|G(y)|},\qquad F_{1,\mathrm{fact}}=\frac{2P_{\mathrm{fact}}R_{\mathrm{fact}}}{P_{\mathrm{fact}}+R_{\mathrm{fact}}}=\frac{2M}{|A(a)|+|G(y)|}.\]

Если названы два из трёх обязательных фактов и нет лишних утверждений, \(P_{\mathrm{fact}}=1\), \(R_{\mathrm{fact}}=2/3\), \(F_{1,\mathrm{fact}}=0.8\). Полная бинарная правильность при этом равна нулю. При одном неправильном третьем утверждении вместо пропуска фактическая F1 станет \(2/3\).

Эта конвенция рассчитана на ответы по заданной рубрике: дополнительные факты вне \(G(y)\) считаются лишними. Если задача допускает полезные добавления, заранее расширяют список допустимых фактов или вводят отдельную разметку их корректности; нельзя объявлять любое отсутствие в кратком эталоне фактической ошибкой. При пустом ответе и непустом эталоне F1 равна нулю; при двух пустых множествах — не определена. Оценку отказов эта формула не заменяет.

У развёрнутой инструкции совпадение слов может скрыть потерянное «не» или условие срока. Здесь сопоставляются факты, а не токены: приведённую оценку нельзя отождествлять с библиотечной метрикой без сверки определения. Формула через \(2M\) задаёт нулевой результат и при отсутствии совпадений, когда запись через гармоническое среднее требует отдельного соглашения.

Точность и полнота цитирования

Наличие квадратных скобок ещё не означает опору на источник. Пусть \(A_{\mathrm{cite}}\) — утверждения, которым по правилам задачи нужны ссылки, \(L\) — уникальные пары «утверждение, приведённый источник», \(S_c\) — набор источников, на которые ссылается утверждение \(c\). Для простого протокола, где каждый источник должен самостоятельно подтверждать привязанное утверждение:

\[\operatorname{CitationPrecision}=\frac{\sum_{(c,d)\in L}e(c,d)}{|L|}.\]

Полнота цитирования (citation recall) проверяет долю требующих ссылки утверждений, которые действительно подтверждены совокупностью своих ссылок:

\[\operatorname{CitationRecall}=\frac{\sum_{c\in A_{\mathrm{cite}}}\mathbb{1}[S_c\ne\varnothing]\,e(c,S_c)}{|A_{\mathrm{cite}}|}.\]

Вторая формула допускает совместное доказательство несколькими источниками; первая — более строгая оценка каждой связи. Для утверждений, неизбежно требующих нескольких источников, нужен отдельный протокол полезности ссылки в группе. Такие более тонкие проверки есть в ALCE; не следует выдавать приведённую простую формулу за точную реализацию всех его метрик.

Допустим, ответ содержит три обязательных факта, но ссылки даны только к первым двум. Обе ссылки правильные: точность цитирования равна \(1\), полнота — \(2/3\). Если ссылка к третьему факту ведёт на документ о тарифах, точность упадёт до \(2/3\), а полнота не изменится. При этом сам третий факт может быть верным: качество текста и качество его атрибуции различаются.

При \(|L|=0\) точность не определена; если утверждения требуют ссылок, полнота равна нулю. При \(|A_{\mathrm{cite}}|=0\) полнота не определена. Неверный или несуществующий ID ссылки считается неподтверждающей связью, а не удаляется из знаменателя. Разделение точности и полноты опирается на постановку Liu et al.; единицу разметки и правила совместного доказательства фиксируют явно.

Отказы: доля ответов и риск

Система, отказывающаяся отвечать всегда, не выдумывает факты, но бесполезна на ответимых вопросах. Поэтому качество среди выданных ответов показывают вместе с долей ответов (answer coverage). Пусть \(u_q=1\), если система дала содержательный ответ, \(u_q=0\) при отказе, а \(\ell_q=1\) при ошибочном содержательном ответе и \(0\) при корректном. Для отказов технически положим \(\ell_q=0\): множитель \(u_q\) исключает их из числа ошибок и из знаменателя риска. Тогда:

\[\operatorname{Coverage}=\frac{\sum_{q\in Q}u_q}{|Q|},\qquad \operatorname{Risk}=\frac{\sum_{q\in Q}u_q\ell_q}{\sum_{q\in Q}u_q}.\]

Избирательный риск (selective risk) — частота ошибок среди выданных ответов, а не среди всех запросов. Если система ответила на шесть вопросов из десяти и ошиблась в двух, coverage равна \(0.6\), risk — \(1/3\). При полном отказе coverage равна нулю, risk не определён. Частичные ответы относят к одной из категорий по заранее заданному правилу.

Сравнивайте риск при сопоставимой доле ответов и отдельно показывайте отказы на ответимых вопросах и необоснованные ответы на неответимых. При настройке порога отказа получается кривая «доля ответов — риск»; снижение риска за счёт отказа от большинства задач не является безусловным улучшением.

Усреднение и неопределённость

Для оценки \(m_q\) макроусреднение даёт каждому вопросу одинаковый вес:

\[\bar m=\frac{1}{|Q_{\mathrm{valid}}|}\sum_{q\in Q_{\mathrm{valid}}}m_q.\]

Здесь \(Q_{\mathrm{valid}}\) — вопросы, где оценка определена. Рядом публикуют число исключённых случаев: иначе система с частыми отказами может выглядеть лучше. На пустом наборе среднее не определено; это относится и к формулам правильности, доли ответов и парной разности. Микроусреднение долей сначала складывает числители и знаменатели; длинный ответ с большим числом утверждений получает больший вес. Если ответы имеют доли подтверждения \(1/1\) и \(1/9\), макросреднее равно \(5/9\), микросреднее — \(2/10\). Это разные оценки, а не ошибка округления.

Для сравнения систем A и B на общем непустом наборе вопросов с определёнными оценками обеих систем считают парную разность:

\[\Delta=\frac{1}{|Q|}\sum_{q\in Q}(m_q^{B}-m_q^{A}).\]

В парном бутстрепе (paired bootstrap) многократно выбирают вопросы с возвращением, сохраняя обе оценки одной пары вместе, и каждый раз считают \(\Delta^\ast\). Процентильный интервал между квантилями \(0.025\) и \(0.975\) — приближённый доверительный интервал. Он отражает выборочную неопределённость при принятой схеме выборки, но не ошибочную разметку или перенос на другой домен. Для связанных вопросов одного диалога или документа перевыбирают целые группы.

Расчёт на практике

Код рассчитывает уже размеченные оценки; он не умеет сам определять логическое следование. Сохраняем неопределённые значения как None.

def fraction(numerator, denominator):
    return numerator / denominator if denominator else None

def fact_f1(matched, generated, required):
    return fraction(2 * matched, generated + required)

# Три утверждения: два подтверждены контекстом, два совпали с эталоном.
supported = [True, True, False]
faithfulness = fraction(sum(supported), len(supported))
f1 = fact_f1(matched=2, generated=3, required=3)

# Третье утверждение осталось без ссылки; две имеющиеся ссылки верны.
link_support = [True, True]
claim_cited_support = [True, True, False]
citation_precision = fraction(sum(link_support), len(link_support))
citation_recall = fraction(sum(claim_cited_support), len(claim_cited_support))
print(round(faithfulness, 3), round(f1, 3))  # 0.667 0.667
print(citation_precision, round(citation_recall, 3))  # 1.0 0.667
assert fact_f1(0, 0, 3) == 0
assert fact_f1(0, 0, 0) is None
assert fraction(0, 0) is None

RAGAs и инструменты оценки цитат могут автоматизировать часть разметки, но версии метрик и инструкции судье нужно сохранять рядом с результатами. Установите, какие поля они читают: ответ, контекст, эталон или только вопрос. Формулы с одинаковыми именами могут отличаться деталями. В этом разделе приведён явный протокол, а не обещание побитового совпадения с API библиотеки.
