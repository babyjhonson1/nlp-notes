# Практика по LLM-агентам

Три большие работы на одном примере выбора книги. Основной код пишет читатель; в тетрадях находятся условия, данные, каркас и проверки. Подсказки и разбор решения — по ходу работы. Не нужно делать отдельную лабораторную после каждого раздела.

| Работа | Что отрабатываем | Состояние |
| --- | --- | --- |
| [1. От workflow к агенту](01_workflow_and_agent.ipynb) | StateGraph, состояние и переходы; вызовы нескольких инструментов, сообщения, ошибки, остановка; подключение HF | Готова к решению |
| 2. Agentic RAG и память | Управление поиском, отбор инструментов и контекста, сохранение условий между шагами, сравнение с фиксированным RAG | Запланирована |
| 3. Надёжность, оценка и Langfuse | Подтверждение, восстановление, повторные операции, сценарии оценки; чтение трасс, задержки и токены | Запланирована |

Обучение tool calling разбирается в конспекте; подготовка траекторий и маски потерь — дополнительное упражнение. Тяжёлое обучение и отдельная обязательная работа по multi-agent не нужны для первого прохода главы.

## Запуск первой тетради

Из корня репозитория (Python 3.11 или новее; проверено на 3.13.2):

```sh
python3 -m venv practice/agents/.venv
practice/agents/.venv/bin/python -m pip install -r practice/agents/requirements.txt
```

Открой `01_workflow_and_agent.ipynb` в VS Code с расширениями Python/Jupyter и выбери Python из `practice/agents/.venv` в меню ядра. Также можно пользоваться своим Jupyter. Если нужен JupyterLab, установи и запусти его в том же окружении вручную:

```sh
practice/agents/.venv/bin/python -m pip install jupyterlab
practice/agents/.venv/bin/python -m jupyter lab practice/agents/01_workflow_and_agent.ipynb
```

Команды выше — для macOS/Linux. Ядро — Python-процесс, в котором исполняются ячейки. Оно должно использовать окружение с установленными зависимостями.

Соседние `lab01_support.py` и `lab01_checks.py` должны оставаться рядом: это готовые данные, инструменты, адаптер и проверки. Решения пиши непосредственно в ячейках `TODO`. До их заполнения ошибки `NotImplementedError` ожидаемы. После решения перезапусти ядро и выполни ячейки заново, чтобы исключить зависимость от старых переменных.

Чтобы сохранить исходный шаблон, можно сделать копию `01_workflow_and_agent.local.ipynb`: такие копии исключены из Git. Для разбора укажи путь к своему файлу; присылать секреты и весь вывод ячеек не нужно.

## Hugging Face

Основная часть бесплатна и работает без LLM. Для настоящей модели предусмотрен `HFModel` через Hugging Face Inference Providers: вычисления идут у провайдера, веса не загружаются на ноутбук. Нужны аккаунт, токен с разрешением вызова Inference Providers и доступная модель с поддержкой tools. Полная инструкция и отключённая ячейка запуска находятся в тетради.

На 2026-10-10 [официальные условия](https://huggingface.co/docs/inference-providers/pricing) требуют покупки кредитов для бесплатного аккаунта; сам аккаунт не даёт бесплатную квоту. Конкретная модель пока не выбрана: доступность и поддержка инструментов зависят от провайдера. Ключ вводится через `getpass`, а не сохраняется в ячейке. Удалённые запросы при подготовке тетради не выполнялись.

## Langfuse

LangGraph задаёт исполнение графа. Langfuse позволяет исследовать запуски LLM-приложения: вложенные вызовы, входы и выходы, задержки, токены и оценки. В конспекте он появится в разделе «Оценка и диагностика», а в третьей практике — как инструмент разбора ошибок и сравнения изменений. Обзор всех функций сервиса не планируется. [Официальная интеграция с LangChain/LangGraph](https://langfuse.com/integrations/frameworks/langchain).

Первую работу можно решать сейчас; переписывание теоретических разделов идёт отдельно. После неё достаточно прислать путь к тетради и вопрос или ошибку. Основные механизмы решения остаются работой читателя.
